# 实盘准入清单(Phase 6,人工步骤)

> **结论先行:按当前证据,不应该上实盘。**
> 日线趋势策略在玉米上**没有发现可延续的优势**,旧回测还受换月跳空污染;晋级门槛(`docs/adr/20261109-promotion-gate.md`)一项都没通过。
> 15 分钟基准(用购买的分钟线重做,见 `docs/adr/20261110-baseline-15m.md`)的结论**同样是负面**:测试段 -20.2%、夏普 -1.08,成本吞掉了全部毛利。
> 本清单是"将来某个策略通过门槛之后"的流程,而不是现在就去做。实盘切换需要用户另行明确授权。

## A. 策略准入(代码与数据,我可以做)
- [ ] 数据已复权(`CADJ/MAADJ`),并有足够长的样本外(见晋级门槛 ADR 的最少年数表);
- [ ] 通过晋级门槛全部 9 条(`risk/promotion_gate.py::check_gate` 输出为空;前 8 条对应 11 个失败原因,夏普上下界与回撤双口径各算一条门槛的两个方向;第 9 条 DSR ≥ 0.95,未计算或缺试验次数也算未通过);并用 `python scripts/record_promotion.py` 写出 `data/state/promotion_approval.json`——
      没有这个文件,`run_headless.py` 拒绝连接生产 API(`实盘` 且非 SimNow;见 `docs/adr/20261111-discipline-enforcement.md`);
- [ ] **若这份策略要走 `approved/` 装载**(即从批准目录装载候选而不是用 `strategies/` 里的受信骨架),
      还要有**装载门**的批准记录 `data/state/approved_promotion.json`——它与准入门是**两份独立的记录**,

      **今天没有任何候选通过过门槛 → 这份记录不存在 → `approved/` 装载这条路是关着的**;
- [ ] 随机入场对照分位 ≥ 95%,成本翻倍后夏普 ≥ 1.0;
- [ ] 测试段只看过**一次**,看后没有再调参;
- [ ] 回测成本换成期货公司**真实费率**(不是"3 元/手"的假设)。

### A2. 新候选策略的额外约束(2026-11-10 起生效)

## C. 期货公司与穿透式监管认证(只有你能做)
> 以下流程基于一般做法,**具体以你开户的期货公司为准**,2025 年起程序化交易还有报备规定,请向对方确认。

1. 开户前向客户经理确认:
   - [ ] 是否支持 CTP 程序化接入?AppID / AuthCode 怎么申请?
   - [ ] 申请与测试环境是否收费?
   - [ ] 程序化交易是否需要报备?怎么报?
   - [ ] 程序化账户的手续费、保证金、**最低入金**有没有特殊规定?(1 万元能否开户)
   - [ ] 测试环境要跑多久才能开通生产环境?
2. 登记你的程序(软件名称、版本),拿到测试环境账号与 AppID/AuthCode;
3. 把 `.env` 的 `CTP_ENVIRONMENT` 设为 `测试`(看穿式测试环境用测试版 API),在测试环境跑满对方要求的天数;
4. 通过后获得生产环境的 AppID/AuthCode,`CTP_ENVIRONMENT` 改回 `实盘`。

### C2. 运行机与终端信息(2026-11-10 起)
实盘与穿透测试在**另一台 Windows 机器**上**直接用 Python 运行**,不用 Docker、不在开发机上跑。
理由:穿透式监管上报的是真实运行环境的 IP/MAC/硬盘序列号;容器里读到的是容器的信息,与宿主机对不上会被驳回。
树莓派(ARM64)不可行:CTP 官方库只有 x86_64,见 `docs/adr/20261109-deployment-and-live-mode.md` §5。

在**那台运行机上**(项目根目录)依次执行:
```bash
python scripts/collect_terminal_info.py --public-ip --out terminal-info.txt   # 终端信息采集(照着填采集表)
python scripts/run_headless.py --check                                        # 配置与依赖自检,不连接
python scripts/penetration_check.py --confirm-broker-test                     # 连测试环境走一遍,生成脱敏报告
python scripts/penetration_check.py --confirm-broker-test --with-order        # 交易时段:再加跌停价买单+撤单
```
- 采集脚本输出里标了 `[出网]` 的网卡才是实际访问期货公司前置的那块;**运行机上不要开 TUN/VPN 类代理**
  (开发机上默认路由走虚拟网卡 `198.18.0.x`,采到的 MAC/IP 会是虚拟网卡的,见 runbook §8)。
- 演练报告写在 `data/penetration/`(不入库):步骤结果 + 脱敏网关日志,可作为"测试留痕"交给期货公司;
  账号只保留头尾 2 位,密码/授权码/AppID 全部替换为 `***`。交给对方前仍请自己通读一遍。
- `CTP_ENVIRONMENT=测试` 才会走看穿式测试环境;`实盘` + 非 SimNow 地址 = 生产 API,演练脚本**直接拒绝**。
  没拿到测试环境参数之前,可以用 SimNow 地址预演脚本本身(`实盘` + SimNow 前置),但那**不算**期货公司的穿透测试。
- 自动重启:没有 `docker-compose` 的 `restart: on-failure:3`,用 Windows 任务计划程序(开机/失败时重启)或 NSSM 把
  `run_headless.py` 注册为服务,并遵守退出码语义——**退出码 0(含硬锁定后空仓)不得自动重启**,2/3/4 最多重试几次;
  日志目录 `.vntrader/log` 与风控状态 `data/state/` 需保留(无人值守证据表读它们)。
- 步骤结果为 FAIL 时的排查:`授权验证失败` 先核对 AppID/AuthCode 与 BrokerID 是否属于**同一个环境**(测试与生产的授权码不通用);
  `4097 网络读失败` 见 runbook §8(地址/代理),与账号无关。

### C2b. 生成国信《外部接入系统技术测试报告》(可重复)
国信要求每次(新版本、AppID 变更、模板更新)提交穿透式 + 程序化两份测试报告。在运行机上(`.env` 已填国信测试环境参数与 `BROKER_TEST_*`):
```bash
python scripts/broker_test.py --confirm-broker-test --interactive     # 逐项取证(含 2.1 断网演练);非交易时段先跑一遍
python scripts/broker_test.py --confirm-broker-test --resume data/broker_test/<目录>   # 交易时段补测 SKIP 的项
python scripts/broker_report.py --template <国信模板.docx> --evidence data/broker_test/<目录>
```
- 终端会列出"报告里还缺什么"(未通过/未测试的项、没填的字段、需人工签字盖章)。**不会默认勾通过**。
- 运行期间**关闭运行机的自动重启**,一次运行只登录一次(国信会检查频繁登录、会话数、退出后是否正常注销)。
- 国信测试环境参数在模板里(IP/端口/BrokerID),不入库;AppID 按 `client_系统名称_版本号` 命名且与实盘一致。
- 证据图是渲染图不是界面截图,**先向国信确认是否接受**;设计与局限见 `docs/adr/20261111-broker-test-compliance.md`。
- **跑之前先确认账户空仓**:有持仓时取证运行器会拒绝发单(所有发单项记 FAIL 并提示先人工处理)——因为「无仓位可平」「暂停期间平仓」这类演示单会真的平掉仓位。
- **核对打印出来的前置地址**:脚本无法用连接结果判断「连的是不是国信测试前置」(测试版 API 与生产前置不通用握手),入口会打印交易/行情前置地址,必须人工确认。
- 报告里**选测项没通过也不勾「测试结论:通过」**;证据图文件缺失会在终端点名,不会交出一份缺图的报告。

## E. 永远成立的纪律
- 不手动改止损、不手动提前平仓、不在账户里手动开仓(对账会拒绝启动);
- 触发硬锁定后先查明原因,不要立刻解锁;
- 连续多次触发当日熔断说明策略或行情假设已失效,回到 A 重新验证,不是调大阈值。
