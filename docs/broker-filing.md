# 程序化交易报备说明(草稿)

> 用途:向期货公司报备程序化交易时,"程序是什么、有什么风控"的事实性材料。**只写仓库里能核实的事实**,
> 期货公司的具体格式与要求以对方给的模板为准;标 ⚠ 的是需要你补充或向对方确认的项。
> 当前策略在回测中没有发现可延续的优势(见 `docs/live-readiness.md`),报备/穿透测试通过**不代表**可以上实盘。

| 项 | 内容 |

## 2. 策略类型与交易频率
- 策略:趋势跟随 + ATR 止损(日线 `trend_atr_strategy.py`;15 分钟基准 `trend_atr_15m_strategy.py` 仅研究/回测)。
- 属于低频、中短线趋势策略,**不是**高频/做市/套利策略;日线版本每个交易日最多产生一次信号,开平仓都用限价单。
- 本地止损:止损单在本地依赖 Tick 触发(不是交易所条件单),因此有"行情停更"看门狗(见 §3)。
- ⚠ 日内最大委托笔数、撤单率请以 `config/risk_manager_setting.json` 的阈值为上限填写(见 §3),并向期货公司确认其口径。

## 5c. 跑一次正式取证的操作顺序(北京时间)

**能跑的时段**:只有交易时段能跑发单类项目——周一到周五日盘 09:00–15:00(含两段休息)与夜盘 21:00 起;
周五夜盘延续到周六 02:30(部分品种更早收);**周六 02:30 之后到周一 09:00 之前完全休市,周日没有夜盘**。
非交易时段发单类项目会标「未测试」,一键流程会拒绝开跑(要加 `--force`,但那会白耗一次登录额度)。
SimNow 第二套(7x24)只供 API 测试,撮合/行情/流控与真实时段不同,**不能代替预演**。

**一键就够**:预演与正式都是一条命令,清场不是必经步骤——

| 场景 | 命令 |
|---|---|
| SimNow 预演(先跑这个,报告**不能交国信**) | `python scripts/guoxin_oneclick.py --rehearsal` |
| 国信正式取证 | `python scripts/guoxin_oneclick.py` |

一键流程自带空仓闸门:账户空仓就一路跑下去;**真有持仓**时一笔单都不发、停下并写明原因,
只有这时才需要下面的第 1 步清场(清场会发真实平仓单,所以必须人工 `--confirm-flatten`,不做成自动)。

1. **(仅当闸门报「账户已有持仓」时)清场**。有残留持仓时,空仓闸门会把**所有**发单项判 FAIL(那是账户状态,不是代码坏了)。
   交易时段内执行,**必须带 `--profile .env.guoxin`**:
   `python scripts/flatten_positions.py --profile .env.guoxin` 先看它打算平什么(只看不动),
   确认无误再加 `--confirm-flatten` 真发单;留痕在 `data/flatten/*.json`。
   - **计划里有「买入平仓」时还要加 `--confirm-direction`**:净持仓账户的净多会被报成空头,那一单可能是**加仓**;
     这个工具会动真实仓位,所以方向没在交易客户端核对过就不放行(退出码 2,不发任何委托)。
   - **为什么不带档案不行**:一键流程(`guoxin_oneclick.py`)会把项目 `.env` 换成国信档案再取证,跑完还原。
     如果在「换成国信档案」和「还原」之间跑了不带 `--profile` 的清场,`.env` 里还留着**另一个**档案的地址,
     平掉的就是**另一个账户**的仓位。所以清场工具:进程环境变量与**项目 `.env`** 不一致(且没指定档案)→
     拒绝运行(退出码 2);**指定了 `--profile` 时,不一致只是 ⚠ 提示**(操作员已经明说要用哪个档案,
     进程环境里的残留值不该永久挡住这个用法),此时以**档案**的值为准。
     没指定档案 → 用项目 `.env`,也会在结果里写明用的是哪个档案。
   - 清场工具还会在这些情况下**拒绝发单**:白名单为空(没说清连哪台)、行情前置不在白名单(平仓价来自行情盘口)、
     上期所/能源中心的今昨仓拆不出来(只提示人工平仓,`vnpy_ctp` 只在纯昨仓时写 `yd_volume`)。
   - 收尾时如果交易通道不在线,**查不到持仓 ≠ 没有持仓**:工具会明确说「持仓查询不可信」并以退出码 4 退出,
     这时不能当成「账户已空」,要人工去柜台核对。
2. **正式取证**:`python scripts/guoxin_oneclick.py`(会切 `.env` 档案 → 取证 → 出报告 → 还原 `.env`)。
   非交易时段要加 `--force`(否则它会拒绝白耗一次登录额度)。
   预演用 `--rehearsal`(连 SimNow,产出**不能交国信**)。
3. **3.1 断网演练**需要人工配合:按提示断开本机网络、恢复网络,再
   `python scripts/guoxin_oneclick.py --resume <证据目录>` 补测。
4. **报告**在证据目录里(`证据与报告目录:<路径>`)。签字(第五页)与四处盖章必须人工。
5. 还需人工做的:在采集信息齐全的机器上跑国信原版采集自检工具并登录,然后通知国信技术部。

## 5f. SimNow 侧的几个发现(2026-11-16 夜盘)
这一节记的是**工具本身**的问题,和国信前置通不通无关——正式取证迟早要用上。

1. **柜台的合约表查询要 90 秒以上**。实测:2026-11-13 用 90.0 秒、2026-11-16 用 91.6 秒,
   偶尔一次 300 秒都没等到。原来 `broker_test.py` / `penetration_check.py` 的连接超时是 120 秒、
   `flatten_positions.py` 是 180 秒 —— **国信正式取证只要柜台同样慢,就会在登录这一步超时退出(退出码 3),
   拿不到任何证据**。三个脚本的默认超时已统一改成 300 秒。
2. **同一个采集窗口会落进两次持仓快照**。清场工具因此生成过**两张 3 手平多单**(账户只有 3 手),
   超平会被柜台**整单拒**(错误码 30「CTP:平仓量超过持仓量」),仓位没平掉。
   根因已核对 `vnpy_ctp` 源码:**不是「柜台推两遍」** —— 一次持仓查询回报用 `(合约, 方向)` 做键、
   `last=True` 时推完就清缓存,不可能推两行同键;是**网关自己每约 4 秒自动查一次持仓**,
   采集器又把回报记成没有请求/响应边界的平铺列表,两份快照混进了同一个窗口(所以是**间歇性**的)。
   现在按 (合约, 方向) 合并、取**最后一次快照**那行:**求和是错的**(平仓量翻倍),
   **取最大也是错的**(那是挑一个更旧、更大的数去平)。
   合并还解决不了「键消失」:柜台对**已平掉**的合约不再推持仓事件,所以后一次快照里没有的合约
   = 已经平掉了,留着它就会去平一个不存在的持仓(柜台整单拒)并误报「未平干净」。
   现在按到达时刻把回报分批,**只在最后一批是紧邻前一批的子集时**才丢掉消失的合约;
   判不出来就保守保留全部(宁可多留一行,也不能少平一手)。
3. **SimNow 账户的 `c2701.DCE Long 3` 是真实持仓**(柜台查询回报确认,不是 OMS 旧缓存),
   2026-11-16 22:01 已按计划平掉:3 手 @ 2175.0 全部成交,收尾复查持仓 0 项。
   留痕:`data/flatten/flatten-20261116-215903.json`。
4. **预演里四个项目判 FAIL,查下来全是工具的问题**(不是柜台、也不是账户):
   - **演示把账户锁成了「当日禁止开仓」**:用跌停价以下的买单制造柜台硬拒绝,硬拒绝触发账户风控的
     当日锁定 ⇒ 之后 200 笔稳定运行只放行了 9 笔,其余全被「账户处于DAILY_LOCKED」拦下(实测 191 条)。
     「无足够资金开仓」场景**改为不演示**(制造资金不足的两条路都会毁掉这一轮),记为「需在专用小资金账户补测」;
     「接收柜台错误提示」改用**平仓超量**演示(柜台回错误码 30,平仓被拒不锁账户),只要真收到一次柜台错误文本即通过。
   - **风控计数是异步更新的**:报单/撤单计数在委托回报事件里 +1,不等计数涨上去就发下一笔,
     「超过阈值的委托」会被放行(实测 T6/P3.1 判成「未被拦截」)。现在先等计数稳定、再等计数推进到 base+1 才发下一笔;
     **计数没推进时判 SKIP 而不是 FAIL** —— 那是「没法判定」,判成 FAIL 会把证据写成「阈值失灵」,方向反了。
     两条口径钉死:①等的是**本指标管的那个计数**,而且**撤单指标必须等完撤单再判** ——「汇总撤单笔数」
     只在撤单回报里 +1,提前等必然等不到,这一项会永远判 SKIP(假件里被「挂单超时自动撤单」掩盖);
     ②「判不出来」只认「委托发出去了但计数没动」,委托压根没发出去是实打实的失败(FAIL)。
   - 复核(codex 第二轮)又补了三种「判不出来」,都判 SKIP 不判 FAIL:
     ①**计数基数取旧**(设置阈值后重新读计数,此刻已 ≥ 阈值 = 基数是旧的,对照做不成);
     ②计数**一次跳不止 +1**(别的回报混进来);③**撤单没确认**(我们自己的单没拿到 `CANCELLED` 终态,
     那一轮的触发就不是我们要演示的那一次)。配套:`cancel_active` 等到撤单**终态**再返回
     (否则单子还挂在柜台上、下一项指标拿到的还是旧基数)。
   - **本地风控的告警被当成了柜台错误提示**:本地风控同样写 ERROR 级别日志。现在「柜台错误提示」
     只收交易网关(CTP)的日志,其他网关的日志只留痕。
   - 补一道**运行前闸门**:账户被锁(硬锁定/当日锁定)时取证直接拒绝连接,不浪费一次券商登录额度;
     稳定运行项在锁定状态下判「需补测」,而不是记一笔「放行 0 笔」。
     (闸门本身也修了:状态文件**读不出来/坏了**原来一律当成「没锁」照跑,现在判不出来 → 拒绝跑并说明原因。)
5. **持仓方向的键不能用 `direction.value`**(复核发现的、语言相关的坑)。vn.py 的 `Direction` 是被 gettext
   翻译过的枚举(`LONG = _("多")`):英文 locale 下 value 是 'Long',中文/`C` locale 下是 '多'
   (本机实测三种 locale 三种文案),`.name` 才恒定。合并键取 value ⇒ **键随机器语言变** ⇒ 同一份持仓
   在两台机器上归出不同的键 ⇒ 合并漏行(该平的没平)。现在键一律用枚举名,给人看的文案固定中文
   ('多'/'空'/'净'),报告交到国信手里不会因为机器 locale 不同变成英文。
6. **净持仓账户的盲区(代码在 `vnpy_ctp` 那边,改不了,但要知道)**:`vnpy_ctp` 的 `DIRECTION_CTP2VT` 是从
   `DIRECTION_VT2CTP` 反推的,键 `'1'`(PosiDirection=**净**)与 D_Sell 撞车 ⇒ **净持仓账户的净多会被报成空头**。
   双边持仓账户不受影响(实测 SimNow 报 `c2701.DCE Long 3`),但两者在 vnpy 侧长得一样,代码里分不出来
   ⇒ 清场工具的计划里遇到「买入平仓」会**点名提示**,而且**不放行自动发单**:那种情况下这单可能是**加仓**,
   请先在交易客户端核对方向,再加 `--confirm-direction` 才发。
