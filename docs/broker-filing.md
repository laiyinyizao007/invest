# 程序化交易报备说明(草稿)

> 用途:向期货公司报备程序化交易时,"程序是什么、有什么风控"的事实性材料。**只写仓库里能核实的事实**,
> 期货公司的具体格式与要求以对方给的模板为准;标 ⚠ 的是需要你补充或向对方确认的项。
> 当前策略在回测中没有发现可延续的优势(见 `docs/live-readiness.md`),报备/穿透测试通过**不代表**可以上实盘。

## 1. 基本信息
| 项 | 内容 |
|---|---|
| 软件名称 | ⚠ 按期货公司要求填写(本项目为基于 vn.py 的自研脚本集合,仓库名 `invest`) |
| 软件版本 | ⚠ 以提交时的 git 提交为准:`git rev-parse --short HEAD` |
| 底层框架 | VeighNa(vn.py)4.5.0(开源,MIT 协议;⚠ 如期货公司需要授权文件,请先与对方确认) |
| 交易接口 | CTP(`vnpy_ctp` 6.7.11.4,封装上期技术 CTP API);看穿式监管认证使用期货公司发放的 AppID/AuthCode |
| 运行环境 | 一台固定的 Windows 机器,直接用 Python 运行;终端信息见 `collect_terminal_info.py` 的输出 |
| 账户形态 | 单账户(`.env` 一套配置);GUI 平台层面支持多网关,但项目默认不启用,账户风控按单账户监控 |
| 交易品种 | 商品期货,当前研究品种为玉米(大商所 C);⚠ 报备时请按实际拟交易品种填写 |

## 2. 策略类型与交易频率
- 策略:趋势跟随 + ATR 止损(日线 `trend_atr_strategy.py`;15 分钟基准 `trend_atr_15m_strategy.py` 仅研究/回测)。
- 属于低频、中短线趋势策略,**不是**高频/做市/套利策略;日线版本每个交易日最多产生一次信号,开平仓都用限价单。
- 本地止损:止损单在本地依赖 Tick 触发(不是交易所条件单),因此有"行情停更"看门狗(见 §3)。
- ⚠ 日内最大委托笔数、撤单率请以 `config/risk_manager_setting.json` 的阈值为上限填写(见 §3),并向期货公司确认其口径。

## 3. 风控措施(均有代码与测试)
下表阈值取自 `config/risk_manager_setting.json`(2026-11-10),以文件当前内容为准。

| 层 | 措施 | 阈值/行为 | 位置 |
|---|---|---|---|
| 委托前 | 单笔手数 / 单笔金额 | ≤ 2 手 / ≤ 100000 元 | vn.py `riskmanager`(`SafeRiskManagerApp`) |
| 委托前 | 日委托/撤单/成交上限 | 委托 200、撤单 100、成交 100(合约维度同) | 同上 |
| 委托前 | 活动委托数 / 重复报单 | ≤ 10 / ≤ 10 | 同上 |
| 账户 | 当日亏损熔断 | 当日亏损 ≥ 600 元:撤单 → 平仓 → 当日停止交易 | `risk/account_guard.py` |
| 账户 | 累计回撤硬锁定 | 回撤 ≥ 2000 元:平仓 → 确认空仓 → 退出 → 重启拒绝交易,需人工解锁 | 同上、`scripts/unlock_account.py` |
| 账户 | 滞留开仓委托撤销 | 开仓委托超过 120 秒未成交自动撤销 | `trading/guard_rule.py` |
| 账户 | 废单风暴 / 撤单锁定 | 600 秒内废单 ≥ 3 次触发废单风暴处置;单日撤单 ≥ 50 次当日禁止开仓 | 同上 |
| 废单 | 错误码三级分类 | 硬拒绝(锁仓)/ 软拒绝(重试)/ 未知(按硬拒绝) | `risk/order_policy.py`、ADR `20261110-ctp-error-code-and-watchdog-policy.md` |
| 行情 | 行情假死看门狗 | 交易时段内长时间无 Tick:撤开仓挂单并告警(平仓单不动) | `trading/runtime.py` |
| 连接 | 断线状态机 | 交易/行情通道分别记录连接状态并告警 | ADR 同上 |
| 启动 | 对账 | 账户有非本策略持仓、持仓与策略状态不一致 → 拒绝启动 | `trading/runtime.py` |
| 运行 | 策略异常看门狗 | 策略被引擎异常停止 → FATAL 告警并紧急平仓 | 同上 |
| 运维 | 告警通知 | Webhook(通用/飞书/Telegram),密钥脱敏 | `notify/webhook.py` |

> 取证运行器(`scripts/broker_test.py`)对国信负责的三条行为约定:**会发真实委托**(所以发单前统一过空仓闸门,有持仓一笔不发);
> **一次运行只登录一次**(国信会查会话数与频繁登录)——例外是 3.1 断网演练:断网后用 `--resume` **另起一轮**补测,
> 那是两轮各登录一次,不是一轮里登两次;**退出前发登出请求并固定等待**(见 ADR「优雅登出」)。
> 前置地址现在**由脚本判别**:交易前置与行情前置都必须在 `BROKER_TEST_ALLOWED_TD/MD` 白名单内
> (`ctp_tools/broker_targets.py` 是地址表的唯一来源),一键流程会自动注入这两个白名单,
> 运行期再校验一次——「柜台环境=测试」这个标记本身不说明连的是哪台机器。
> 白名单**只能收窄**:代码里写死的可信前置全集之外的白名单条目一律丢弃并告警(白名单与地址同源,采信它等于自证清白);
> 白名单为空 = 操作员没说清连哪台 → 拒绝连接。
> 白名单还**按经纪商代码绑定**:国信档只认国信前置,SimNow 档只认 SimNow 前置(两个是不同的账户、不同的柜台,
> 混搭就可能平到不是取证那个账户的仓位上)。
> 行情前置同样要查:它喂回来的盘口价会直接变成委托价,连错行情前置 = 用假价格下单。

## 5c. 跑一次正式取证的操作顺序(北京时间)

1. **先确认账户空仓**。有残留持仓时,空仓闸门会把**所有**发单项判 FAIL(那是账户状态,不是代码坏了)。
   交易时段内执行,**必须带 `--profile .env.guoxin`**:
   `python scripts/flatten_positions.py --profile .env.guoxin` 先看它打算平什么(只看不动),
   确认无误再加 `--confirm-flatten` 真发单;留痕在 `data/flatten/*.json`。
   - **为什么不带档案不行**:一键流程(`guoxin_oneclick.py`)会把项目 `.env` 换成国信档案再取证,跑完还原。
     如果在「换成国信档案」和「还原」之间跑了不带 `--profile` 的清场,`.env` 里还留着**另一个**档案的地址,
     平掉的就是**另一个账户**的仓位。所以清场工具:进程环境变量与**项目 `.env`** 不一致(且没指定档案)→
     拒绝运行(退出码 2);**指定了 `--profile` 时,不一致只是 ⚠ 提示**(操作员已经明说要用哪个档案,
     进程环境里的残留值不该永久挡住这个用法),此时以**档案**的值为准。
     没指定档案 → 用项目 `.env`,也会在结果里写明用的是哪个档案。
   - 清场工具还会在这些情况下**拒绝发单**:白名单为空(没说清连哪台)、行情前置不在白名单(平仓价来自行情盘口)、
     上期所/能源中心的今昨仓拆不出来(只提示人工平仓,`vnpy_ctp` 只在纯昨仓时写 `yd_volume`)。
   - 收尾时如果交易通道不在线,**查不到持仓 ≠ 没有持仓**:工具会明确说「持仓查询不可信」并以退出码 4 退出,
     这时不能当成「账户已空」,要人工去柜台核对。
2. **正式取证**:`python scripts/guoxin_oneclick.py`(会切 `.env` 档案 → 取证 → 出报告 → 还原 `.env`)。
   非交易时段要加 `--force`(否则它会拒绝白耗一次登录额度)。
   预演用 `--rehearsal`(连 SimNow,产出**不能交国信**)。
3. **3.1 断网演练**需要人工配合:按提示断开本机网络、恢复网络,再
   `python scripts/guoxin_oneclick.py --resume <证据目录>` 补测。
4. **报告**在证据目录里(`证据与报告目录:<路径>`)。签字(第五页)与四处盖章必须人工。
5. 还需人工做的:在采集信息齐全的机器上跑国信原版采集自检工具并登录,然后通知国信技术部。
