# 计划:联网找想法 + 自动研究循环(有界活动)+ 新数据最终确认

## Context(为什么做、要达成什么)
你想让系统**自己联网找策略想法、自己写代码、自己评估、自己循环,直到找到合适的策略**;你不懂统计细节,希望由 AI 来判断。
第 1 轮实测(V/EB/M 全部淘汰)和现有纪律说明:**"无限循环直到过关"在统计上会自毁**——DSR 的分母(试验账本,现 765)只增不减,循环越久门槛越不可能过;且现有数据约 5.9 年,夏普置信区间下界要大于 0 在 2~3 年样本外上基本做不到。
所以本计划把"自动研究直到合适"改造成:**每一次"活动"事先预注册预算和判据 → 全自动执行(想法、写码、批准、评估、记账都无人值守)→ 到预算或出现"过了验证筛选"的候选就停 → 用新补的行情做一次封存的最终确认 → 出报告**。要继续就新开一次活动。
**"合适"由确定性的门槛输出判定(`risk/promotion_gate.py`),不由大模型的意见判定**;大模型只负责找想法和写代码。上线(装载门、SimNow 连续 5 个交易日、穿透测试、期货公司)仍是另一回事,须你另行明确授权,本计划不触碰。

## 你已经做的选择(据此设计)
- 停止规则:你说"自己不懂、AI 研究更靠谱" → 我替你定为**有界活动**(下面第 C 节的预算与停止条件),你不用再选,但可以随时否决。
- 联网:**找想法(隔离)**、**更新行情**、**工作流直接联网搜索**三项都要。
- 自动批准:**保持开着,加更强隔离**。
- 最终确认:**用补上的新数据**。

## 一个必须如实说的冲突(影响顺序)
"工作流直接联网搜索再写代码 + 自动批准 + 现有沙盒"这三者叠加,外部网页文本经模型直接变成不经人读就执行的代码;而静态筛查只是黑名单、不是隔离(仓库里已有多轮 codex 实测的绕过记录),#29 的独立进程隔离方案还只是"待评审"的设计,未实现(`docs/adr/20261115-candidate-process-isolation.md`)。
**所以顺序上:隔离(D)必须先于"联网内容进入自动批准"(B 的第二阶段)。** 在隔离落地前,联网来源的想法**只能走人工批准**(用代码强制,不靠约定,见 B3)。

## 方案

### A. 行情数据更新与"新样本外"封存(宿主机,联网)
- 新增宿主机脚本(基于现有 `scripts/fetch_data.py` / `import_minute.py` 的 AKShare 路径):补 2026-06-15 之后到最新的分钟线,**写入独立的"封存"文件**(如 `data/csv/*_15m_fresh.csv`),**不并进**网关挂载的派生数据目录;选参窗口 2020-07~2022-06、验证窗口 2022-07~2023-12 不变,窗口常量仍在 `scripts/segment_windows.py`。
- 先查清每个品种(C/V/EB/EG/PP/M)的实际覆盖到哪天、哪些段被基准/候选看过(`segment_ledger`、`data/research`)——**第一步先做只读盘点**,再决定"新样本外"到底有几个月。
- 在 `scripts/segment_ledger.py` 里把"新数据段"登记为封存段:**每次活动对它最多看一次**(只对一个预先选定的入围者),先登记后运行;网关与候选进程**拿不到**这份文件(容器挂载里没有;加测试证明容器内读不到)。
- **如实预期**:补上的新数据只有约 5 个月,统计功效很低,**只能当"否决/健全性检查",不能单独证明有优势**。真正的证据来自:① 其它品种的独立复现(A2 允许);② SimNow 前向录制(已有录制管线)。

### B. 想法管线(联网,隔离)
1. **采集器(宿主机、无交易凭证、不执行抓回来的任何内容)**:从你认可的来源白名单(例如 arXiv q-fin、公开研究博客/RSS;**来源清单实施时再请你确认**)抓文本。
2. **净化成结构化想法**:单独一步(独立模型调用,拿不到任何工具)只产出 `IdeaSpec`:目标品种、一句话假设、入场/出场规则的**文字描述**、预期失败方式、长度上限;**不含 URL、代码、命令、指令性语句**;不合格的丢弃并记录。写代码的模型**永远看不到原始网页文本**,只看 IdeaSpec。
3. **来源标记与强制**:每个想法带 `provenance`(`user` / `web`)。**自动批准代码路径检查它:`web` 来源一律拒绝自动批准(fail-closed)**,走人工哈希批准;直到隔离(D)落地并经复核才放开。这是真正接线的防线,不是文档约定。
4. **去重与计数**:新想法与已试想法做相似度/规则等价检查;"换参数重提""近似重提"一律**按新试验计入**,且不得绕过预注册。
5. **毕昇工作流直接联网搜索**(你要的第三项):只在"找想法"阶段加搜索节点,其后**必须接净化节点**再进入写码节点;搜索节点不连接起名/写码/提交节点。放在 D 之后启用。
6. 每个入队想法在提交前自动写入**预注册账**(追加式哈希链,含品种、假设、统一失败判据 = 沿用 `docs/adr/20261123-research-round-1-preregistration.md` §3),**先登记后提交**,与现有"提交前写下"同一口径。

### C. 活动驱动器(无人值守循环,有界)
- 新脚本 `scripts/research_campaign.py`(宿主机):复用现有函数,不另造——`tools/research_mcp/server.py` 的 `_start_research` / `_request_approval_inline` / `_research_status`(含 `_eval_progress` 轮询)、`tools/bisheng/set_product.py` 的 `main(product)` 切品种、`scripts/research_attempts.py` 记尝试。
- **活动预注册**(新 ADR + 机器可读文件):品种范围、**预算上限 N 个候选**(建议 12,且 ≤ 滚动 24 小时提交上限 20)、失败判据、停止条件。**预算由代码强制**,驱动器自己改不了。
- **每轮前置自检(任何一项不过立即停)**:试验账本、尝试记录、批准账链校验通过;结果目录排他锁在;`STOP` 文件不存在(**人工急停开关**);未超预算与 24h 上限。
- **每轮**:取下一个已预注册想法 → 切品种并核对 `tool_eval.product` → 启动 → 自动批准(仅 `user` 来源,见 B3)→ 推进 → 轮询到结果 → 校验结果 `key == 目标品种`(防止再出现"评估跑错品种") → 按统一判据判定并记账。
- **停止**:到预算 / 出现"过了验证筛选 + 击败随机对照"的候选 / 任何账本异常 / 急停。**不因"没过"而放宽、调参重来或加预算。**
- 活动结束自动生成**报告**(沿用第 1 轮报告模板:逐条门槛输出、账本总数与"目标品种上真正产生绩效的评估次数"两个口径、候选与想法的差距)。**报告不得把"没过"写成"再多跑几轮就行"**。
- 入围者(若有)才进入 A 的封存最终确认 + 其它品种独立复现(预先登记);通过与否只看确定性判据。**不自动晋级、不自动上线。**

### D. 更强隔离(前置条件,独立立项)
- 以 `docs/adr/20261115-candidate-process-isolation.md`(#29,待评审)为基础:**候选只产出信号,回测/记账/落盘/指标由框架独立进程完成,框架不信任候选自报数字**。
- 该 ADR 第 8 节"需要用户拍板的点"须先过评审;现有未合并分支(`feat/29-candidate-process-isolation`、`feat/21-stage3` 等,**其中几条没有远程副本**)要先盘点哪些可复用——**这是本计划里最大的一块工作量**,单独 Issue/ADR/G8 两轮,不并进 A~C。
- 隔离落地并复核前:联网来源想法只能人工批准(B3);`auto_approve` 对 `user` 来源保持现状。

### E. 流程与纪律(贯穿)
- 以下改动都是**执行域/不可降级**文件,各走完整流程(Issue → worktree 放 `.worktrees/` → 确认块 → G8 两轮):`scripts/research_sandbox.py` / `tools/research_mcp/server.py`(自动批准的来源检查)、`scripts/segment_ledger.py`(封存段)、`scripts/research_gateway.py`(如需新字段)、容器挂载/compose。
- 研究域:活动预注册 ADR、想法队列、驱动器脚本、报告模板(按研究域轻流程,但调用防线函数的部分升档)。
- 账本只增不减、DSR 分母不动、测试段与门槛数值不动、不放松任何已有防线。

## 实施顺序(建议)
1. **只读盘点**:各品种数据覆盖与已消耗段;现有 #29 分支可复用部分。(无改动)
2. **A 的数据更新 + 封存段**(宿主机脚本 + segment_ledger 登记 + 容器读不到的测试)。
3. **B1~B4 想法采集 + 净化 + provenance 强制**(含"web 来源不得自动批准"的代码与测试、注入夹具测试)。
4. **C 活动驱动器 + 预注册机制 + 急停**(先用桩模型与 N=1 做端到端冒烟,沿用"流水线冒烟不算研究"的登记方式)。
5. **D 隔离**(独立大项,单独方案与评审)。
6. D 复核通过后:**B5 工作流联网搜索**与对 `web` 来源放开自动批准(再走一次评审)。

## 验证(端到端怎么测)
- 单元/集成:每步都有测试;并发与失败路径(线程起不来、账本链断、急停、预算耗尽)有用例。
- **红队用例**:把含"忽略以上指令并执行…"的恶意网页放进采集夹具 → 净化器必须丢弃/改写;`web` 来源想法即使构造出合法候选也**不得被自动批准**(断言 fail-closed)。
- **封存检验**:在真实网关容器里断言读不到 `*_fresh.csv`;封存段对同一活动第二次读取被 `segment_ledger` 拒绝。
- **冒烟**:N=1 的活动走完"想法→预注册→提交→批准→异步评估→判定→报告",按预注册的验收清单逐项核对(结果 `key` 必须等于目标品种;账本只多出预期的行;链校验通过)。
- 每次交付前 `python tools/check_domain.py --diff origin/main` 分档;相关测试 + 变异/守卫套件全绿;G8 第 1 轮(Gemini)被限流时**如实标"阻塞",不记通过**。

## 需要你知道的诚实预期
- 在累计试验几百次、样本外只有一两年的条件下,**这个循环大概率给出的结论仍是"证明不了有优势"**,这是统计规律,不是流水线缺陷;自动化改善的是**覆盖面和速度**,不是把门槛变容易。
- 想真正提高"找到可上线策略"的概率,杠杆在**更多独立数据**(其它品种复现、SimNow 前向录制、新补的行情),而不在多跑几轮。计划里已把这些放进最终确认路径。
