## 2. 定量诊断:门槛里哪几条是「被数据卡住」的

晋级门槛 9 条里,与样本量直接耦合的是这三条:

1. 样本外往返 ≥ 150(统计意义)
2. 样本外夏普 ≥ 1.5(点估计)
3. 夏普 95% CI **下界 > 0** → 需要 `夏普 > 1.96/√样本外年数`

第 3 条的门槛值随**样本外年数**变化(实测 `sharpe_standard_error`):

| 样本外年数 | 要求夏普 > | 可行区间(与「≥1.5」取交) |
|---|---|---|
| **1.5 年(现在)** | **1.96** | (1.96, 3.0] ← 极窄 |
| 2 年 | 1.70 | (1.70, 3.0] |
| 3 年 | 1.39 | (1.50, 3.0] ← 开始有戏 |
| 4 年 | 1.20 | (1.50, 3.0] |
| 5 年 | 1.07 | (1.50, 3.0] |
| 8 年 | 0.85 | (1.50, 3.0] |
| 10 年 | 0.76 | (1.50, 3.0] |

**读法**:在 1.5 年样本外上,第 3 条要求的夏普(1.96)已经**高于**第 2 条(1.5),
两条几乎重合 → 它们不是「两道独立的关」,而是同一道关的两面。
要把可行区间拉开,只有一条路:**样本外年数翻倍,要求的夏普降 √2**。

反向读更有用——**「一个真实夏普 X 的策略,需要多长样本外才可能过 CI 那关」**:

| 策略真实夏普 | 需要样本外年数 | 说明 |
|---|---|---|
| 1.5 | > 1.71 年 | 现在是 1.5 年,**差一点** |
| 1.2 | > 2.67 年 | |
| 1.0 | > 3.84 年 | 对期货策略不算差 |
| 0.8 | > 6.0 年 | |

**目标定在 4 年样本外**:那样真实夏普 ≥1.0 的策略都有机会过 CI 关;
真实夏普 1.2 的需要 2.7 年,1.5 的只要 1.7 年(现在只差 2 个月)。

### 2.1 往返数那条为什么不用单独操心

基准策略在 18 个月里产生 ~148 笔往返 → 约 **0.4 笔/交易日**(约每 90 根 K 线一笔)。
所以「往返 ≥ 150」与「样本外 1.5 年」是**同一个约束的两种说法**。

想把往返数提上去有两条路:
- **加长样本外**:往返数随时间线性涨,成本不变;
- **加密交易**:往返数涨,但**成本(滑点+手续费)直接吃掉边际**,
  而且门槛第 5 条(成本翻倍后夏普 ≥1.0)会先卡住你;交易次数多也意味着更多过拟合自由度。

→ **加长时间比加密交易划算得多。** 这条决定了下面三条路径的排序。

## 3. 三条数据路径

### 3.1 补购更长的历史(最高杠杆)

**为什么它的杠杆最大**:现在的选参窗吃掉了 2020-07~2022-06,验证窗只剩 18 个月。
**更长的历史不是「加长尾巴」,而是「把验证窗整体往后推、推得更宽」**——
历史从 2015 年开始的话,选参窗可以用 2015~2020,验证窗直接变成 2020~2024(4 年)。

| | 现在 | 补购后(目标) |
|---|---|---|
| 历史起点 | 2020-07 | 2015 或更早 |
| 选参窗 | 2020-07~2022-06(2 年) | 2015~2020(5 年) |
| 验证窗 | 2022-07~2023-12(1.5 年) | 2020-2024(4 年) |
| CI 关要求的夏普 | >1.96 | >1.20 |
| 可行区间 | (1.96, 3.0] | (1.50, 3.0] |

- **代价**:钱。第一份 5.9 年的 15m 已经买过一次(记忆里记着),这次要更长。
- **时间**:一次采购 + 导入 + 重跑基准,**几周到几个月**,不是几年。
- **要买什么**:见 §4。
- ⚠️ **买回来的数据要走 `scripts/import_minute.py` 合成复权连续**,不能直接用分合约原始文件
  (换月跳空会污染回测——日线那条就是这么废掉过一次,见 `20261109-negative-backtest-result.md`)。

### 3.2 CTP 自录(长期兜底 + 填「实盘可行性」的证据缺口)

设施**已经齐了**:`scripts/record_market_data.py`(常驻,Tick + 1 分钟)、
`record_market_data_wrapper.py`(子进程生命周期)、`record_market_incremental.py`(DSH cron 的有界增量),
SimNow 第一套前置已验收(2026-11-12 夜盘)。

| | 说明 |
|---|---|
| 它买到什么 | **只往前长,不补历史**。2026-06 起每天录 → 2028-06 才有 2 年新数据 |
| 对样本外的作用 | 验证窗可从 1.5 年推到 3.5 年(2024-2028)——**比补购慢两年** |
| 副产品(可能更重要) | ① **真实成交记录**——`live-readiness.md` §A 缺的「实盘可行性」证据;② **真实滑点与手续费**——现在的「3 元/手」是假设值,换成期货公司真实费率才能过 §A 最后一条 |
| 生命周期边界 | ADR `20261111-market-recording-and-dsh-orchestration.md`:**DSH Desktop 关闭期间不承诺继续录制**;`@goodandready/dsh-cron` 的外部运行器有界超时,不能承载长期前台进程 → 用 wrapper 独立 child |

**结论**:它不是解决样本量的捷径,但它是**唯一能拿到真实费率与真实成交**的路径,
而那两条是实盘准入清单上现在还空着的格子。**应该现在就常驻跑起来,不是因为它快,
是因为它慢——晚启动一个月就少一个月的数据。**

### 3.3 多品种 / 多周期(第二条腿)

每个品种/周期是**独立**的样本外,合计年数相加:MA 的 15m + C 的 15m = 2×1.5 = 3 年。

⚠️ **代价必须诚实记**:门槛第 9 条 DSR 按**试验次数**去通胀。
品种越多、候选越多,试验次数越多,DSR 越严。所以多品种**不是免费的**——
它同时增加了「要找到好策略」的工作量,也增加了「要证明的不是过拟合」的工作量。

**建议**:多品种排在补购历史**之后**——先把 C15 的验证窗拉长,再考虑开第二个品种。

## 4. 补购需求清单(要买什么)

| 项 | 规格 | 理由 |
|---|---|---|
| 周期 | **15 分钟**(与现有 C15 口径一致) | 换周期=换策略族,不能直接拼;5m 数据更缺但要先确认 15m 够不够 |
| 品种 | 玉米 **C** 优先;有余力再买 MA | MA 是对照品种,独立样本外 |
| 历史起点 | **≤2015-01-01**(目标);最低 2018 | 见 §3.1 的窗口换算 |
| 复权 | **分合约原始数据**(我们自己合成复权连续) | 买来的「复权主力连续」不可信:换月规则各家不同,且无法复核 |
| 交付格式 | 与第一次一致的 DCE 分合约 1 分钟/5 分钟档 | 复用 `scripts/import_minute.py` |

**验收口径**(买回来之后):
1. `scripts/import_minute.py` 合成后,`derived/C_15m_adj.csv` 行数与年限符合预期;
2. 与现有重叠区间**逐根比对**价格一致(新数据不能改写历史);
3. 换月点无跳空(与日线那次同样的检查);
4. 重跑 15m 基准 → 成绩单**可能与现在不同**(数据变了)——**如实记录,不回头改门槛**。

## 5. 录制常驻化的具体做法

| 步骤 | 动作 | 验收 |
|---|---|---|
| 1 | 定一台常开机器(Windows 运行机或专用小主机),`CTP_RECORD_PROFILE` 指向 SimNow 或看穿式测试 | `validate_config` 通过;连上后不订阅的 `stalled` 检测不触发 |
| 2 | 用 `record_market_data_wrapper.py` 独立 child 起,不由 DSH cron 承载前台进程 | child 存活;DSH 关闭不影响它 |
| 3 | DSH cron 只做 `ensure`/`watchdog` 的**有界短任务** | 演练:DSH 重启后进程树干净、锁释放、PID 不复用 |
| 4 | 每日报一次入库行数与最后时间戳 | `docs/runbook-market-recording.md` 的证据表 |
| 5 | 每周把录到的 1 分钟数据合成 15m 复权连续,进 `derived/` | 与买入数据的重叠区间一致 |

**已知边界**(必须写进 runbook,免得日后误判):
- DSH Desktop 关闭 → 不录制(ADR 已记);
- 第二套 7×24 前置的行情时间不可信 → 不用它做质量判据;
- 录到的是**真实市场数据**,不是我的模拟——它能填「实盘可行性」的证据,但**不能**当样本外证据用
  (同一段行情,研究者已经看过 → 多重检验偏差)。

## 6. 每一步解锁哪条门槛

| 动作 | 解锁 | 单独做完能不能过全部门槛 |
|---|---|---|
| 补购到 2015(验证窗 4 年) | CI 下界那条的要求从 1.96 降到 1.20 | **不能保证**——还要看策略本身有没有货(§7) |
| CTP 自录(2 年新数据 + 真实费率) | CI 那条的年数 +1.5;§A 费率那条 | 不能保证,但**填上两个现在空着的格子** |
| 多品种(MA 15m) | 合计样本外年数 +1.5 | 不能保证,且 DSR 会更严 |
| 这批候选(5 个不同思路族) | **判断「思路族有没有货」** | 这不是数据问题,是思路问题 |

## 7. 这件事与「候选全是负面的」的关系

两件事**必须分开**:
- 如果 5 个不同思路族**全是负面的** → 不是数据不够,是**思路没货**(该换思路族:配对交易、跨品种、期限结构、做市回归…);
- 如果有**正面的但被「往返不足/置信区间」卡住** → 是数据问题,按 §3 补数据。

这正是这批候选存在的意义:**用一次实验把这两个假设分开。**

## 8. 兜底:如果攒够了还是过不了

诚实的结论是:**「在这段数据、这个周期、这个品种上,没能证明有统计优势」**——
这不是失败,是**研究结论**。它意味着:
- 要么换标的/周期(但每个都要重新证明);
- 要么接受「这个策略不能上实盘」,继续用日线基准做研究;
- **绝不能**做的事:放宽门槛、延长验证窗多看几次、把门槛阈值调松(ADR `20261109-promotion-gate.md` 明令禁止)。

---

## 9. 不做什么

- 不改门槛数值、不改窗口口径、不动测试段纪律(那是「事后放宽」,明令禁止);
- 不用**已经看过的**那段行情充当新的样本外(自录的数据同样如此);
- 不为了凑数反复调参刷往返数(DSR 第 9 条会记账,而且这正是过拟合);
- 不在能力隔离(#38 那类)做完之前打开 `approved/` 的实盘装载路径。
