## 1. 这三个视图是什么

它们让你看见**大模型在后台怎么改进策略**的全过程,分三个维度:

| 视图 | 回答的问题 | 数据来源 | 阶段 |
|---|---|---|---|
| 进化曲线 | AI 整体有没有在变聪明? | 谱系台账 `data/research/evolution/<campaign>.jsonl` | ④ |
| 参数热力图 | 选出来的策略是不是"纸老虎"? | 热力图文件 `data/research/heatmaps/<run_id>.json` | ④ |
| 代码与变异日志 | AI 每次为什么这么改? | 谱系台账 + `pending_strategies/` 里的源码 | ④ |

**谁在产生这些数据**:进化回路由**毕昇(Bisheng)工作流**承载——生成一代、提交评估、读结果、反思、下一代。
毕昇界面里能看到每个节点的实时输入输出(那是"过程"的第一层);本页三个视图是"结果"层,用于看长期趋势和审计。
**页面不做任何写操作**:没有"注入变异""淘汰候选""批准""回滚"按钮,一个都没有(见 §7)。

## 2. 三个接口

| 接口 | 用途 | 关键参数 |
|---|---|---|
| `GET /api/research/evolution` | 战役列表 | 无 |
| `GET /api/research/evolution/{campaign_id}/curve` | 进化曲线 | 路径参数 |
| `GET /api/research/evolution/{campaign_id}/log` | 变异日志 | `cursor`、`limit`(默认 50;上限取配置的 `evolution.log_limit`) |
| `GET /api/research/runs/{run_id}/heatmap` | 参数热力图 | 路径参数 |
| `GET /api/research/candidates/{sha256}/code` | 候选源码(按哈希) | 路径参数 |
| `GET /api/research/candidates/{sha256}/diff` | 两个候选的差异 | 路径参数 `sha256`、查询参数 `parent`(父代哈希,必填) |

全部是 `GET`、全部需要令牌、全部只读。

**可见性**:`GET /api/meta` 的 `capabilities.evolution` 为真时,这几个接口才存在(路由随阶段④上线才注册),
前端才显示进化视图的入口。为假时调用会得到 404 —— 这不是故障,是"该阶段还没上线"。

**战役列表的字段**:`campaigns[]` 是已统计的战役(**按修改时间倒序**,新的在前);
`total` 是总数、`checked` 是本次实际统计的数量、`unscanned` 是没检查的数量。
**`unscanned > 0` 时区块的 `state` 是 `unknown`**——剩下的战役可能有坏台账,
前端不要把列表显示成"一切正常"。列表里**不会**出现代表"未统计"的假战役行。
(契约规定前端『先看 state』,所以这个信号落在 `state` 上,而不是另设一个级别字段。)

### 当前状态:数据还没有
引擎侧(毕昇工作流与研究网关)还没开工产生这些文件,所以现在这几个接口会返回**空**或**缺失**。
**这是如实状态,不是故障**。前端用 `docs/web/fixtures/` 里的 12 个示例数据开发:`evolution-list`、`evolution-list-empty`、
`evolution-curve`、`evolution-curve-stagnant`、`evolution-log`、`evolution-log-page`、`evolution-heatmap`、
`evolution-heatmap-plateau`、`candidate-code`、`candidate-code-missing`、`candidate-diff`、`candidate-diff-missing`。

## 3. 进化曲线(左上)

### 3.1 数据
`curve.points[]` 每项代表**一代**:

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `generation` | 代号(1, 2, 3…) | X 轴 |
| `count` | 这一代有多少个候选 | 显示在 X 轴标签旁(如"第 3 代 · 5 个候选") |
| `elite_sharpe` | 这一代的**最高**夏普 | 折线的主线 |
| `mean_sharpe` | 这一代的**平均**夏普 | 折线的第二条线 |
| `p25_sharpe` / `p75_sharpe` | 种群中间 50% 的区间 | 画成**带**(band) |
| `best_total_return` | 最好收益 | 副轴折线 |
| `worst_max_drawdown` | 最差回撤 | 副轴折线 |
| `cells` | 这一代出现的格子(质量多样性) | 作为分组或 tooltip 补充 |

**服务端算好,前端只画**。不要自己算均值或分位数。

### 3.2 画法
- **X 轴**:代(整数刻度,不要用日期)。
- **左 Y 轴**:夏普。**不要从 0 开始截断**——夏普可以是负的;纵轴范围按数据自适应,但要包含 0 这条参考线。
- **右 Y 轴**:收益(百分比)。左轴夏普、右轴收益,**两轴都要标单位**,否则读者会把 2.0 夏普和 2.0% 收益混淆。
- **种群带**:P25–P75 画成半透明色带,P75 在上、P25 在下;精英线画在带之上,均值线用虚线。
- **图例**必须区分:`精英`、`均值`、`P25–P75`、`收益(右轴)`。
- **提示标志**(`curve.flags[]`)以**卡片上方的横幅**呈现,不要塞进图里:
  - `kind: "stagnant"` → "连续 N 代精英夏普没有提升";
  - `kind: "overfit_suspect"` → "第 N 代精英夏普比种群均值高 X:可能是个别候选的偶然高分,请看热力图判断是否稳健"。
  - 标志的 `level` 是 `warn`,用警示色。**文案是提示,不是结论**——原样显示服务端的 `text`,不要改写成更确定的说法。

### 3.3 "怎么看好坏"(这是给人看的说明,前端**不要**自己实现判定)
- **健康**:精英线阶梯式上升,均值线同步跟上,带宽度稳定。
- **停滞**:精英线长期横平 → 服务端会给出 `stagnant` 标志。此时该做的是换变异方向,不是继续加代。判据是**窗口之前的历史最好**:正在稳步进步的战役不会被说成停滞。
- **过拟合警报**:精英线陡升但均值线不动(带很宽)→ 服务端给 `overfit_suspect`。**必须引导去看热力图**:如果那个高分只对应一个孤零零的格子,就是过拟合。
- **注意**:精英线上升**不等于**策略可用。晋级仍然只认沙盒的晋级门槛 + 人工批准,这条前端不要在文案里暗示能被绕过。

## 4. 参数热力图(右上)

### 4.1 数据
`heatmap.grid` 是**二维**得分表 `grid[y][x]`:
- `axes.x` / `axes.y`:两轴的名字与取值。
- `axes.z`:被切出来的第三轴(`selected` 是它的下标)。
- `grid[y][x]`:该参数组合的夏普。**`null` 表示无效**(例如往返笔数不足),**不是 0**,也不是负数。
- `best_cell`:最优格的三维下标。
- `on_plateau`:是否在参数高原上(**服务端判定**,前端不重算)。
- `valid_cells` / `n_cells`:有效格数与总格数。
- `note`:**"分数来自选参窗口,不是样本外表现"**——这句话必须显示,不能省。

### 4.2 画法
- **颜色 + 数值双编码**:每格既有颜色也有数字。只靠颜色对色盲用户不友好,也不满足对比度要求。
- **色阶**:单色渐变(例如深蓝 → 青 → 亮绿),**不要红绿渐变**(红绿是最典型的色盲失败组合)。
- **`null` 格**:用**斜纹或明确的"无效"**图案 + 文案"无效",**不要**画成深色(会被读成极差),也**不要**画成 0。
- **坐标轴**:轴名直接用参数名(如 `breakout_n`、`atr_mult`),刻度用实际取值。
- **高亮**:最优格描边加粗;`on_plateau` 为真时,在图上方显示"在参数高原上";为假时显示"**不在参数高原上**"——这也是重要信息,不要只显示为真的情况。
- **无热力图时**:显示"这次运行没有保存参数网格",不要显示一个空的网格框。

### 4.3 "怎么看好坏"
- **稳健高原**:一大片连续的高分格子 → 策略对参数不敏感,容错高,可以进入人工审核。
- **孤岛尖峰**:四周全黑(低分或无效)只有一格极亮 → 典型过拟合,稍微改一点参数就崩。
- **热力图是二元的**:一个参数在某些组合下好、在另一些下差,说明它不是稳健的。
- **无效格分布**也是信息:大片无效说明该参数范围下策略根本跑不起来。

## 5. 代码与变异日志(下方)

### 5.1 布局
上下两块:
- **上**:变异日志表格(一代一行)。
- **下**:选中某一代后显示该候选的**源码**(带行号)与**与父代的差异**。

### 5.2 日志表格
每行来自 `log.records[]`:

| 字段 | 显示 |
|---|---|
| `generation` | 代号 |
| `status` | 状态徽标(原样显示,不要自己翻译成"成功/失败"——后端可能新增状态) |
| `sharpe` / `total_return` / `max_drawdown` | 数字,统一格式化 |
| `dsr` / `n_trials` | **只展示**。dsr 是多重检验校正后的夏普,`n_trials` 是试验次数。**不要**用它们给候选排序或高亮,也不要在前端计算任何"校正后"的数字 |
| `cell` | 格子标签(小徽标) |
| `diagnosis` | 结构化诊断对象,渲染成键值对 |
| `fail_reason` | 失败原因 |
| `reflection` | **反思自由文本**——用 `PlainText` 组件原样显示 |
| `parent_sha256` / `candidate_sha256` | 哈希,等宽字体,点击"看代码"或"看差异"时传给代码接口 |
| `created_at` | 时间 |

### 5.3 源码与差异
- 源码:接口 `GET /api/research/candidates/{sha256}/code` 返回 `lines[]`(`{n, text}`)。
  用 `PlainText` 组件,等宽字体、保留缩进、**不解析 HTML**、不执行语法高亮插件里的 HTML 渲染。
- 差异:接口 `GET /api/research/candidates/{sha256}/diff` 返回 `diff`(**统一 diff 文本**)。
  渲染方式:按行拆开,`+` 开头用新增色、`-` 开头用删除色、其余用普通色。**必须用文本节点渲染**。
- `available: false` 表示有一份源码已经不在(父代被清理了)→ 显示"父代源码已不在,无法比较",**不是错误**。
- `found: false` → 显示"该哈希的候选源码已不在"。

### 5.4 反思文本的处理(重要)
- 反思是**大模型写的自由文本**,是"不可信输入"。
- 原样显示为纯文本;**不解析 Markdown**(或只允许极受限的纯文本呈现);**绝不 `innerHTML`**。
- 展示时明确标注:**"仅供审阅,未进入模型输入"**。
- 不要把反思文本作为标题、按钮文案或任何可点击元素。

### 5.5 "怎么看好坏"
- 反思里的说法**不是证据**。判断"这次改动好不好"看的是同行的 `sharpe`、`dsr`、`fail_reason` 与热力图。
- 一条常见的形态:精英夏普跳得很高但 `n_trials` 也涨得很快 → 多重检验的风险,提示标志会同时出现。
- 反思说"我改了过滤阈值"但代码差异里没有对应改动 → 这本身是值得注意的现象(模型自述与实际改动不符)。

## 6. 空态、缺失与过期

| 情况 | 显示 |
|---|---|
| 还没有任何战役(`campaigns: []`) | "还没有进化战役(引擎侧还没开始产生记录)"。**不要**显示成一个空图表或错误页 |
| 战役存在但某战役 `state: "corrupt"` | 该行显示"台账损坏或读不了",其余战役照常显示;**整块的 `state` 是 `unknown`** |
| 某个战役的曲线/日志返回 503 | 台账损坏或读不了(**不是 404**)。显示"该战役的记录不可用",不要当成"没有这个战役" |
| 某次运行没有热力图 | "这次运行没有保存参数网格" |
| 源码找不到 | "该哈希的候选源码已不在" |
| 差异不可用 | "父代源码已不在,无法比较" |

**通用规则**:缺失、过期、损坏绝不能显示为正常(与全站一致)。这三个视图属于**可选子系统**,未部署时**不影响**总览的总体级别。

## 7. 明确不做(前端也要遵守)

1. 页面上**不得出现**"注入随机突变""淘汰/晋级""批准""回滚""调整种群"任何按钮或表单。进化由毕昇工作流驱动,批准只能在本机由人执行。
2. **不得**用 `dsr`/`n_trials` 在前端做选择、排序或晋级判断。
3. **不得**根据曲线或热力图自己判定"过拟合"并给结论。服务端给 `flags`,前端显示 `flags` 的原文。
4. **不得**把 `grid` 里的 `null` 当 0 画。
5. **不得**用 `dangerouslySetInnerHTML` 渲染反思、源码、diff、诊断文本。
6. **不得**调用 `status-api.openapi.json` 之外的接口;不得加载外部资源。

## 9. 轮询与分页

- 三个视图都是只读快照,建议**轮询间隔 30 秒**(比阶段①的 8 秒长;进化是分钟级的事)。
- 变异日志用 `cursor` 游标翻页:传 `cursor` + `limit`,响应里的 `next_cursor` 为 `null` 表示到底。
  **不要**用页码;用游标。
- 轮询时如果 `next_cursor` 不为 `null`,不要自动加载更多(用户可能在看某一代的代码)。
