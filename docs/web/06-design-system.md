# 06 设计系统

给前端(含在 Lovable 里构建)的视觉与交互规范。目标风格:**深色冷调、Bento 网格、克制的玻璃拟态**——好看,但**可读性和状态的准确传达优先于装饰**。
功能与状态语义见 [`01-product-spec.md`](01-product-spec.md);本文只管『长什么样』。

## 1. 原则

1. **状态不靠颜色单独表达。** 每个状态 = 颜色 + 图标 + 文字(见 §4)。
2. **玻璃只用在容器上,不用在文字背后叠加复杂背景。** 玻璃面板之下是纯色底,不放渐变光斑、图片、动画背景,否则文字对比度不可控。
3. **一屏一个重点。** 最严重的状态占最大面积、最靠上;其余卡片退后。
4. **动效服务于状态变化,不做装饰。** 数据更新用 150–200ms 淡入;状态变严重时用一次性高亮,不用循环闪烁。
5. **手机上也要读得清。** 半夜看手机是核心场景;`backdrop-filter` 在低端手机上耗电且可能卡顿,必须有降级(见 §3.3)。

## 2. 设计令牌(Design Tokens)

以 CSS 变量定义(Tailwind 通过 `theme.extend.colors` 引用这些变量)。**所有颜色必须来自令牌,组件里不得写死十六进制。**
下表『对比度』是相对对应背景的实测 WCAG 比值(正文要求 ≥4.5:1,大字与图标 ≥3:1)。

### 2.1 深色主题(默认)

| 令牌 | 值 | 用途 | 对比度(底 / 玻璃) |
|---|---|---|---|
| `--bg` | `#0B0F14` | 页面底色 | — |
| `--surface` | `rgba(255,255,255,0.06)` ≈ `#1A1D22` | 卡片(玻璃) | — |
| `--surface-hover` | `rgba(255,255,255,0.10)` ≈ `#23272C` | 悬停/高层 | — |
| `--border` | `rgba(255,255,255,0.12)` | 卡片描边 | 装饰,不承载信息 |
| `--text` | `#E6EDF3` | 正文 | 16.3 / 14.3 |
| `--text-2` | `#9FB0C0` | 次要文字、说明、时间 | 8.6 / 7.6 |
| `--ok` | `#3DDC97` | 正常 | 10.9 / 9.6 |
| `--warn` | `#F5B84B` | 需要关注 | 10.8 / 9.5 |
| `--critical` | `#FF6B6B` | 严重 | 6.9 / 6.1 |
| `--unknown` | `#A3B1BF` | 无法判断/过期/缺失 | 8.8 / 7.7 |
| `--info` | `#5AA9FF` | 中性信息、链接 | 7.8 / 6.9 |
| `--accent` | `#4FD1C5` | 强调、焦点环、选中 | 10.3 / 9.1 |

状态徽标的底色是对应颜色的 18% 叠在背景上,徽标内文字用同一颜色,实测对比度:ok 7.6、warn 7.7、critical 5.4、unknown 6.4、info 5.9,均达标。

| `--bg` | `#F4F6F9` | — |

> 主题切换:跟随系统,可手动覆盖;偏好存 `localStorage`(仅主题,不存令牌和数据)。

### 2.3 排版

| 项 | 规范 |
|---|---|
| 字体 | **系统字体栈**,不加载网络字体:`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`;等宽:`ui-monospace, "SF Mono", Consolas, monospace` |
| 字号 | 基准 14px(桌面)/ 16px(手机);标题 20 / 16;数据大数字 28–32(用等宽数字 `tabular-nums` 防止跳动) |
| 行高 | 正文 1.5;表格 1.4 |
| 数字 | 金额、百分比、手数一律 `font-variant-numeric: tabular-nums` |
| 中文 | 不用斜体;标点全角;不拼接句子(便于文案集中管理) |

### 2.4 间距、圆角、层级

- 间距按 4px 基数:4 / 8 / 12 / 16 / 24 / 32。卡片内边距 16(手机 12)。
- 圆角:卡片 16,徽标/按钮 8,输入框 8。
- 层级:底色 < 卡片 < 悬浮层(下拉/弹层)< 横幅(环境横幅与连接中断横幅永远最上)。
- 阴影:深色下用边框 + 微弱外发光代替阴影;不用新拟态(Neumorphism)——它依赖低对比度的浮雕,与可读性要求冲突。

## 3. 玻璃拟态的使用规则

### 3.1 配方

```css
.glass {
  background: var(--surface);                 /* rgba(255,255,255,.06) */
  border: 1px solid var(--border);
  border-radius: 16px;
  backdrop-filter: blur(12px) saturate(120%);
  -webkit-backdrop-filter: blur(12px) saturate(120%);
}
```

### 3.2 允许与禁止

| 允许 | 禁止 |
|---|---|
| 卡片、侧边栏、弹层使用玻璃 | 在玻璃后面放渐变光斑、图片、动画 |
| 页面底色用单一深色(可有极轻微的纵向渐变,亮度变化 ≤3%) | 文字直接放在无背景的渐变上 |
| 同层级卡片使用同一模糊强度 | 玻璃叠玻璃超过两层 |

### 3.3 降级(必须实现)

```css
@supports not (backdrop-filter: blur(1px)) { .glass { background: #1A1D22; } }
@media (prefers-reduced-transparency: reduce) { .glass { background: #1A1D22; backdrop-filter: none; } }
@media (max-width: 767px) { .glass { backdrop-filter: none; background: #1A1D22; } }   /* 手机不模糊:省电、防卡顿 */
```

## 4. 状态的视觉表达(最重要)

每个状态都是『图标 + 颜色 + 文字』三件套,**缺一不可**:

| 状态 | 图标(lucide 名,可替换为等价) | 颜色 | 文字 |
|---|---|---|---|
| 区块 `ok` | `check-circle-2` | `--ok` | 正常 |
| 区块 `stale` | `clock-alert`(或 `timer-off`) | `--unknown` | 数据已过期 |
| 区块 `missing` | `circle-slash` | `--unknown` | 未找到数据来源 |
| 区块 `corrupt` | `file-warning` | `--warn` | 数据来源损坏 |
| 区块 `unknown` / 未知取值 | `help-circle` | `--unknown` | 无法判断 |
| 总体 `ok` | `shield-check` | `--ok` | 一切正常 |
| 总体 `warn` | `triangle-alert` | `--warn` | 需要关注 |
| 总体 `critical` | `octagon-alert` | `--critical` | 严重 |
| 总体 `unknown` | `help-circle` | `--unknown` | 无法判断 |
| 事件 `severe` / `warning` | `octagon-alert` / `triangle-alert` | `--critical` / `--warn` | 严重 / 警告 |

规则:
- **`unknown`、`stale`、`missing` 共用灰调(`--unknown`),与 `ok` 的绿色明显不同。** 绝不用绿色表示『没有告警所以正常』——必须先确认数据新鲜。
- 过期态:整张卡片内容降低到 60% 不透明度,卡片头显示过期徽标。仍可读。
- 环境横幅:`live` 用 `--critical` 底色加粗『实盘』;`simnow` / `guoxin-test` 用中性蓝灰;`unknown` 用 `--warn`。横幅高度固定、不随滚动消失。
- **盈亏颜色与状态颜色分离**:盈亏用独立令牌 `--gain` / `--loss`(默认国内习惯:红涨绿跌,可在设置里互换),且必须带符号。**不得复用 `--ok` / `--critical` 表示盈亏**,否则红色会同时代表『亏损』和『严重』。

## 5. 布局:Bento 网格

### 5.1 网格

- 桌面(≥1280px):12 列网格,间距 16;卡片跨 3 / 4 / 6 / 12 列。
- 平板(768–1279px):6 列,卡片跨 3 / 6。
- 手机(<768px):单列堆叠;顶部固定『环境横幅 + 总状态条』。

### 5.2 各页面的卡片排布(桌面)

**总览**
```
┌ 环境横幅 ────────────────────────────────────────────┐
┌ 总状态条:级别 + 最多 3 条原因 ──────────────────────┐
┌ 交易与风控(6) ─────┐ ┌ 告警(3) ──┐ ┌ 无人值守(3) ─┐
└────────────────────┘ └───────────┘ └──────────────┘
┌ 行情录制(4) ───────┐ ┌ 研究沙盒(4) ──┐ ┌ (阶段②)实时(4) ┐
```
卡片按级别排序(critical → warn → unknown → ok),上图是同级时的默认顺序。

**交易与风控**:顶部进程状态条(整行);下面左侧『权益三件套』(6 列),右侧两条进度条(当日盈亏 vs 熔断线、回撤 vs 死线)(6 列);再下面熔断/硬锁定/暂停/准入四个小状态卡(各 3 列)。

**其它页面**:一个主表格或主文本占满宽度,筛选/说明在上方一条工具栏。

## 7. 动效

| 场景 | 规范 |
|---|---|
| 数据刷新 | 数字变化 150ms 淡入;**不做滚动计数动画**(会掩盖真实数值) |
| 状态恶化 | 卡片边框高亮一次(600ms),并触发 `aria-live`;不循环 |
| 页面切换 | ≤200ms 淡入 |
| 弹层 | 200ms 缩放 + 淡入;Esc 关闭 |
| `prefers-reduced-motion` | 全部动效降为即时切换 |

## 8. 验收清单(设计层)

- [ ] 所有颜色来自令牌;切换主题后全部页面对比度仍达标
- [ ] `critical` / `warn` / `unknown` / `ok` / `stale` / `missing` / `corrupt` 七种状态都有『图标 + 颜色 + 文字』
- [ ] 去掉颜色(灰度截图)后,仍能区分各状态
- [ ] 手机宽度下无 `backdrop-filter`,总览与告警页可读
- [ ] `prefers-reduced-motion`、`prefers-reduced-transparency` 生效
- [ ] 盈亏色与状态色不混用
- [ ] 无网络字体、无外链图片
