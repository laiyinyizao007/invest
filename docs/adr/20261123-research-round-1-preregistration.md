- 档位:研究域(`docs/adr/`)。本文只冻结**这一轮研究怎么跑、什么时候停、怎么算失败**,不是策略、不含任何收益声明,不改任何风控常量与晋级门槛
- 关联:`docs/live-readiness.md`(A/A2 节:准入定义与新候选的额外约束)、`docs/adr/20261110-baseline-15m.md`(两条已建基准)、
  `config/test_segment_usage.json`(测试段登记)。候选池本身由 `20261116-candidate-product-pool`(目前在 `docs/29` 分支,尚未并入 main)冻结,本文把品种名直接写出,不依赖它。
- 触发:用户 2026-11-23 要求「执行研究直到产出合格可以上线的策略」。「直到合格为止」是多重检验(见下),故改为**有界地跑**,并把边界先写下来。

## 为什么不能「跑到合格为止」

每一次研究提交都计入试验账本;试验次数是 DSR 的分母,次数越多、门槛越难过——这套机制就是为了惩罚「一直试到过为止」。
同时,15 分钟基准已用掉 2024-01 ~ 2026-06 这一段做最终确认,现有分钟线约 5.9 年,夏普 95% 置信区间下界大于 0 这一条在 2~3 年样本外上基本不可能通过
(`docs/live-readiness.md` A2 节原话:**不能靠放宽门槛**)。所以这一轮的**合法结果包括「证明不了有优势」**。

## 决定

### 1. 范围
- 仅 **苯乙烯 EB、乙二醇 EG、PVC V、聚丙烯 PP、豆粕 M**,15 分钟周期。
- 不增删品种。扩充规则(样本外往返笔数不足 150 笔 + 规格已核实)的两个条件目前都不满足。
- 评估代码现在拼接的是**时间窗口,不是品种**(`risk/candidate_eval.py::pool_oos`),所以只能**一个品种一个品种地评**;
  「在多个品种间选择」的策略不在本轮范围(改评估代码属执行域,须另走完整流程)。

### 2. 试验次数上限
- 截至本文,试验账本 3 次提交(`seq` 1~3,第 3 次是 `eg_atr_channel_breakout.py`)。
- **本轮最多再提交 3 次**,即试验次数最多 3 → 6。
- 看到结果后改参数、重提同一想法,**算新的一次**,计入上限。
- 到上限即停,不得再加。要加,须新写 ADR 并说明理由。

### 3. 每次提交前必须先写下(追加到本文末「提交记录」表,再提交)
1. 一句话假设;
2. 失败判据;
3. 本次提交消耗哪个品种。

**统一的失败判据**(未另写则按此):候选在**训练/验证段**上的基准分数没有明显高于两条已建基准(`docs/live-readiness.md` A2 节),即淘汰,**不调参重来**。
这条的阈值口径沿用 A2 节,不在本文新增或放宽任何数值。

### 4. 测试段纪律(沿用,不削弱)
- 研究轮内**一律不碰测试段**。研究沙盒本身不暴露测试段,测试段台账(`segment_ledger`)登记「只看一次」。
- 只有**同时**满足以下三点的候选才允许看测试段一次:① 通过训练/验证筛选;② 击败两条基准;③ **用户明确同意**。
- 看之前先登记到 `config/test_segment_usage.json`;看完不得再调参。
- 已知残余(不是本文引入):研究侧存在经本地文件读取测试数据的路径(`research_api.py` 的 `test_segment_read_via_local_file: True`),
  其防线靠既有的筛查与台账,本文不改。

### 5. 停止条件
满足**任一**即停,不再「找更好的」:
- 已提交 3 次;
- 有候选走完测试段(无论结果好坏);
- 出现任何会让试验账本、批准账本、测试段台账失效的异常(先修再继续)。

### 6. 交付物
一份报告,至少包含:每个候选的门槛输出(`check_gate` 的结果,逐条);试验次数增量;消耗了哪些品种的测试段;
对「能否上线」的结论。**报告不得把「没过」写成「再多跑几轮就行」。**

## 不在本文范围

- 「上线」。过门槛之后还有装载门批准记录、SimNow 连续至少 5 个交易日无人值守、穿透式监管测试、期货公司开户与报备;
  切实盘须用户另行明确授权。本文不触碰其中任何一项。
- 任何风控常量、晋级门槛数值、沙盒隔离边界的改动。
