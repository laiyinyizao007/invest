# ADR: 风控底线不可优化,以及明确不做的事

- 状态:已采纳
- 日期:2026-11-11
- 跟踪:Issue [#6](https://github.com/laiyinyizao007/invest/issues/6)
- 依据:`docs/期货交易复盘与人性反思-要点梳理.md` §3–§5(研究文档自身在止损比例上有 2%/3%/可寻优网格并存的矛盾,本 ADR 给出本项目的口径)

## 背景
`PROJECTWIKI.md` 阶段三的路线图里写着"风控底线永不优化"(原为口头承诺,「进新 ADR」),
同一份文档里还散落着"明确不做"清单与"本地止损依赖进程存活"的已接受风险。它们都是**防止被反复重提或被悄悄突破**的约束,
应当有一个稳定的、可被引用的出处。研究资料本身对此也不一致:同一对话里既说 3% 止损是铁律,又把止损倍数放进网格寻优。

## 决策

### 1. 风控底线不可优化
**只有入场/信号参数可以被优化器(`walk_forward_optimizer.py`、`optimize*.py`、未来的 `optimizer/`)与外层 AI 研究员搜索。**
下列量是**固化在代码与配置里的底线**,任何自动搜索、LLM 产出、参数迁移都不得修改:
- 单笔预算(300 元 / 3%)与"超预算则不开仓,而不是缩小止损"(`risk/risk_guard.py::within_budget`)
- 止损只收紧、不放松(`TrailingStop`)
- 账户级双层熔断阈值(当日 600 元、累计 2000 元)、废单风暴与撤单上限(`config/risk_manager_setting.json` 的「账户风控」)
- 平仓永远放行、紧急平仓的有限重试与防重复(见 `20261109-account-risk-lock.md`)
- 晋级门槛(`risk/promotion_gate.py::GateThresholds`)与实盘准入(见 `20261111-discipline-enforcement.md`)

> **口径说明**:ATR 止损倍数(`atr_mult`)属于**策略的入场/出场形状参数**,可被寻优;但它受单笔预算约束——
> 寻优结果若使止损距离装不进预算,该组合按"弃单"计(预算弃单率会如实报告),而不是放宽预算。
> 即:**预算是约束,不是被优化的变量**。

修改上述任何一项都需要:新 ADR 说明理由 + 用户明确确认,不接受"回测显示放宽后更好"作为理由(那正是过拟合的形态)。

### 2. 明确不做(防止被反复重提)
| 事项 | 理由 |
|---|---|
| CPCV(组合净化交叉验证) | 当前数据量(约 5.9 年分钟线、单品种)撑不起;先用 walk-forward + 测试段隔离 |
| 每日自动优化 | 噪声拟合陷阱;最多月度/季度滚动重估,且换参须人工确认 |
| 自建前端(Web 面板/Vue/React/Streamlit) | 维护成本与攻击面;用 Webhook 告警 + 日志 + 命令行足够 |
| 手机 App 自动化下单 | 不可审计、不可对账 |
| 高频/做市/期权卖方 | 与 1 万元账户、固定 1 手、300 元预算的定位冲突 |
| 借钱/杠杆叠加 | 资金纪律,见研究资料 §2 |

### 3. 已接受的风险:本地止损依赖进程存活
策略的止损是**本地触发**(依赖 Tick 与进程),不是交易所条件单。进程死亡、行情停更期间止损失效。
已有的缓解:行情假死看门狗(强撤开仓单并告警)、进程被异常停止时的紧急平仓、硬锁定后进程保持存活直到确认空仓、心跳与 Docker/服务重启语义。
这是**有意接受**的残余风险(交易所条件单会带来另一类问题:无法随策略状态同步、夜盘/换月语义不一致);重新评估的触发条件是"出现一次因进程死亡导致的止损失效"。

## 后果
- 优化器、研究沙盒 API 的任何"可搜索参数白名单"必须不含上面的底线量;这在阶段三引入 `optimizer/` 时作为验收项检查。
- `PROJECTWIKI.md` 里对应的口头承诺改为引用本 ADR。
