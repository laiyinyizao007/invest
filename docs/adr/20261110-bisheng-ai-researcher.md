# ADR: 外层 AI 策略研究员采用 Bisheng 编排,经研究沙盒 API 与确定性内核隔离

- 状态:已采纳(架构决策;实现属远期规划位,见 PROJECTWIKI §2.5 登记表与 §2.4 演进路线阶段四)
- 日期:2026-11-10
- 跟踪:Issue [#1](https://github.com/laiyinyizao007/invest/issues/1)
- 依据:`docs/期货交易的复盘与人性反思.md`(提问 56–59)、`docs/期货交易复盘与人性反思-要点梳理.md` §6
- 关联 ADR:`20261109-use-vnpy.md`(不自研底层)、`20261109-promotion-gate.md`(唯一闸门)、`20261110-walk-forward-optimizer.md`(阶段三引擎化前置)

## 背景

研究资料 §6.1–6.4 描绘的 Alpha Factory 双轨矿工与 Agent 工作流四步,需要一个 LLM 编排载体:
「提出策略/参数假设 → 调沙盒回测 → 读结构化结果 → 迭代」的自动化回路。

内层(vn.py 流程引擎)已建成且确定性可测(全量 643 个测试通过、总覆盖率 88%,门禁 85%),但缺这一回路。
两条底线来自研究资料与既有 ADR:

1. **LLM 不进入交易路径**——风控与发单必须留在确定性内核(研究资料 §6.2「模板限制」、§5.6 文件隔离原则);
2. **LLM 的产出再漂亮,不过晋级门槛就不存在**(`20261109-promotion-gate.md`)。

经平台能力核实(2026-11,Bisheng dataelement/bisheng):单流程内支持成环迭代、并行、
Human-in-the-loop 中途确认;Agent 可挂载自定义工具与知识库;私有化 docker-compose 部署;
知识库支持引用溯源与文件级权限——恰好覆盖本题「围绕确定性 CLI 的成环迭代 + 人工审批节点」。

## 决策

**两层架构**:

- **内层 = vn.py 流程引擎(确定性内核)**:现有 `trading/` + `risk/` + `strategies/` + 研究脚本 + `notify/` + Docker。
  **内层必须能在 Bisheng 完全宕机的情况下独立完成交易与风控**——AI 研究员是可选增益,不是交易路径依赖。
- **外层 = Bisheng 流程编排(AI 策略研究员)**:LLM agent 生成假设、调用研究沙盒、读诊断结果、迭代。

**边界铁律**:外层绝不接触实盘交易、真实发单、CTP 凭据、`.env` 交易段;
唯一交互通道是内层暴露的**研究沙盒 API**(端点白名单见 PROJECTWIKI §2.2);
`promotion_gate.check_gate` 是候选策略进入视野的唯一闸门。

**沙盒状态机(目录即状态)**:LLM 产出策略代码**只能**落 `pending_strategies/`(LLM 唯一可写位置);
经 walk-forward + `check_gate` 全过 + **人工批准**(Bisheng HITL 节点或直接人工)才移入 `approved/`;
内层 runtime 只认 `approved/` 目录代码,**装载动作永远由人执行**——物理级代码隔离,fail-closed。

**硬记忆预算**:外层反馈只携带最近 3 次失败的结构化 Trace(`collections.deque(maxlen=3)` 哲学,
研究资料 §6.3-②);不持久化全历史——这是 Bisheng 工作流设计约束,内层零代码。

**可替换性条款**:全部业务逻辑在内层纯逻辑层,外层只是编排壳;
若 Bisheng 失养,可替换为 Dify/LangGraph 而不动内层一行代码——本决策锁定的是边界与流程,不是平台。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Bisheng(毕昇)** | 私有化部署;单流程成环/并行/HITL 原生支持;中文文档与企业权限模型;知识库可承载「上下文投喂」纪律(研究资料 §5.6) | 重(CPU ≥8 核、RAM ≥32 GB,捆绑 ES+Milvus+OnlyOffice);有 CVE 史(见下) | **采纳** |
| Dify | 社区与插件生态更大、部署更轻 | 工作流与 chatflow 分离;HITL 与企业流程自动化能力弱于本题所需 | 落选(保留为可替换对象) |
| 纯 LangGraph(代码级编排) | 与内层同栈、零额外平台、资源最小 | 等于**自研编排层**(回调图/状态/审计/UI 全自建),与 `20261109-use-vnpy`「不自研底层、精力留给策略与风控」精神相悖;无人工审批界面 | 落选 |
| Coze | 上手快 | SaaS 为主,数据与工作流托管在外部平台,与「外层不接触敏感面」边界哲学不符;私有化成熟度不足 | 落选 |

## 安全约束(决策的一部分,非附录)

1. **版本钉死 ≥ 2.6.0**:CVE-2026-82278(v2.6.0 之前 workflow `run_once` 的 Code 节点 `exec()` 无沙箱 → RCE,CVSS 8.7)。
   不满足即整体暂缓——这是少数「不满足即不做」的硬门槛。
2. **仅内网监听**,不暴露公网。
3. **禁用或白名单 Code 节点**:所有「代码执行」全部在内层沙盒,不用 Bisheng 的 Code 节点跑任何交易相关逻辑。
4. **部署物理分离**:与交易 compose 完全分离,不共享网络与 `.env`;不进交易 VPS(资源也不允许)。
5. 外层工具调用仅限研究沙盒 API 白名单端点;API 网关进程从部署层就拿不到 CTP 段环境变量。

## 影响

- 新增独立部署单元(Bisheng compose);§2.2 架构图增加外层子图(全部虚线,规划位)。
- 研究沙盒 API 先以 CLI 形态(`scripts/research_api.py`,规划位)使用,被真实使用后固化为薄 HTTP 网关——API 固化是外层接入的硬前置(阶段三 → 阶段四)。
- 策略骨架模板(风控写死、只留信号函数空壳)成为内层只读资产,由人维护、有独立单测。
- 网关需新增集成测试与边界负向测试(不存在任何交易域端点)。

## 验证

远期实现期验证(当前无代码,不适用测试基线):

- 外层宕机断耦演练:内层交易与风控不受影响;
- pending→gate→人工批准→approved 全流程演练(4b 退出标准);
- 网关负向测试:任何交易域请求均不存在对应端点;
- 版本与部署约束检查纳入接入前 checklist。

## 未决

- **部署机器**:8 核/32GB 需求既不能进交易 VPS,也可能不宜常驻开发机——开发机 vs 独立内网机,阶段四 4b 前决定,不阻塞 4a(人工驱动 CLI 不需要 Bisheng)。
- CTP 行情自录与补购分钟线是两条新样本外数据来源,与外层数据需求重叠,二选一或并行由届时数据缺口形状决定(见 PROJECTWIKI §2.5 登记表)。
