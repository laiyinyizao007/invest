# ADR: 研究评估按品种选数据与规格(此前写死玉米 C15)

- 状态:已实施(Issue #69);**档位:执行域**(改动了评估的输入:数据文件、合约规格、品种键)
- 关联:`docs/adr/20261123-research-round-1-preregistration.md`、`docs/adr/20261116-candidate-product-pool.md`(规格核实表)、`docs/adr/20261123-research-auto-approval.md`

## 发现

2026-11-24 起跑预注册第 4 次提交(PVC)时发现:评估引擎的数据文件、品种键、品种标识全部写死为玉米
(`walk_forward_optimizer.DATA_FILE=C_15m_adj.csv`、`KEY="C15"`、`SYMBOL="CADJ15"`),
`strategies/instruments.py` 里也只有玉米与甲醇的规格;毕昇工作流的候选生成提示词同样写着「玉米」。
因此**预注册第 3 次(EG)的评估口径实为玉米,不是乙二醇**——它的批准后回测结果本就无人看过,
现明确:**该结果即使日后被读到,也不得当作 EG 的证据**。

## 决定

1. `strategies/instruments.py` 增加 `V15 / EB15 / EG15 / PP15 / M15`,乘数、最小变动价位、国信单边费率取自 20261116 核实表;滑点口径沿用「1 个最小变动价位 + 手续费折点」。
2. `walk_forward_optimizer.PRODUCTS`:品种 → (数据文件, 品种标识)。**文件名由代码映射固定**;`C15` 沿用原 `DATA_FILE`(含 `INVEST_C15_DATA` 覆盖),其余品种取**与 C15 同一目录**下的固定文件名(容器里 `INVEST_C15_DATA` 指向挂载点,其余品种随之;没有新增环境变量,候选代码改不了环境)。
3. 评估接口新增 `product`,白名单是 `research_sandbox.PRODUCTS`(**不依赖交易栈**:父进程与网关不得 import `walk_forward_optimizer`,边界测试锁定),**缺省 C15**,不传即与旧行为完全一致(回滚 = 不传)。
   网关、父进程 `evaluate_job`、子进程 `_evaluate_child` **三处各自**按白名单校验;网关对白名单外的值(含非字符串)返回 400。白名单与数据映射、规格表的一致性有测试锁定。
4. 只改**评估**入口。`backtest` / `gate` 两条旧入口仍是玉米,**本次不动**(范围外,留作已知局限)。
5. 测试段纪律、试验账本口径、晋级门槛数值**均不变**。DSR 分母按全部提交累计(最保守),不按品种拆。

## 不变的东西(核对点)

- 没有改任何风控常量、门槛数值、测试段登记、批准账本逻辑。
- 评估窗口仍由 `build_windows()` 按时间划定,与品种无关。
- 新品种的数据文件是否覆盖足够的验证窗口,由评估本身按既有规则(往返笔数下限等)判定,不另放宽。

## 已知局限

- 品种间的成本口径是**假设值**(同旧口径),实盘前须按期货公司真实费率复核。
- `backtest`、`gate` 入口仍写死玉米。
- 毕昇线上工作流的提示词与 `run_evaluate` 工具参数需同步改动(线上操作,不在本 PR 的代码里;见 CHANGELOG)。
- **成本口径不齐**:`C15` 的手续费仍是 `Instrument` 默认的 3.0(未改,避免动玉米既有基准),而 20261116 成本假设表里玉米是 1.21;新品种用的是核实费率。跨品种比夏普时玉米被多罚,不能直接横比。
- **试验账本不带品种字段**:DSR 分母按全部提交累计(保守),但无法按品种归因。
- **`gate` 与 `evaluate` 的 key 可能不同**:`gate_job` 仍写死 `C15`;`record_promotion` 从 evaluate 的 run_id 取 key,若把 V15 的 evaluate 与玉米的 gate 混用会张冠李戴——**晋级记录前必须核对两者品种一致**(本 PR 不改晋级链路)。
- 装载侧 `write_load_approval` 不校验 key 是否在 `INSTRUMENTS` 里。
- G8:第一轮(zen codereview)因 Gemini 免费档 429 被阻塞,未取得实质结论;第二轮 codex 的 10 条发现,Critical/High 均已修复并加了对应测试(见 PR),`guard_roster` 一条经核实只是「提示」不是失败(同 `test_auto_approval.py` 的既有做法)。
