# ADR: 毕昇工作流端到端冒烟(流水线验证,**不是研究**)

- 日期:2026-11-25
- 状态:已记录;**写于提交任何冒烟候选之前**
- 相关:`20261123-research-round-1-preregistration.md`(第 1 轮已结束)、Issue #84(网关评估改异步)

## 为什么要做
第 1 轮后流水线改了一串(评估按品种、容器账本锚点、策略名规范化、`ArrayManager` 接口筛查、毕昇工具定义补 `product`、提交上限 20、**评估改异步**)。
每一项都单独验证过,**整条毕昇工作流从想法到报告没有完整走过一遍**——异步评估只经毕昇的 `/tool/test` 验证过,没经过工作流节点与 MCP 的 `research_status` 轮询。用户要求端到端验证。

## 性质(写死,防止事后改口径)
- **这是流水线验证,不是研究。** 它的结果(夏普、门槛、通过与否)**不用于任何研究结论、不进入任何晋级判断、不构成第 2 轮**,也不改变第 1 轮的结论。
- 不测试段、不碰任何门槛数值与防线。
- 试验账本照常记(**只增不减**):预计 +1 次提交 +125 个网格格子(639 → 约 765)。最终报告里单列为「冒烟」。

## 做什么
- **品种:C15(玉米)**。理由:基准成绩单与此前全部评估都在玉米上,换品种会再给一个新品种的验证窗口多看一眼;用玉米不引入新品种的选择偏差。
- **想法(刻意最朴素的已知模式,不是新假设):** 15 分钟玉米上,收盘价突破前 N 根 K 线最高(最低)价时顺势入场,ATR 止损。
- 一次,走**完整真实路径**:`start_research`(毕昇工作流:起名→生成代码→提交)→ 自动批准 → `research_status` 推进 → 工作流 `tool_eval` 异步启动并立即返回 → `research_status` 按 `run_id` 取状态直至出报告。

## 流水线验收(通过/不通过只看这些,不看策略好坏)
1. 每个阶段都到达,工作流**不再报 10541 读超时**;
2. 提交阶段:候选名不含 `.py`、通过新静态筛查(不因接口误用被拒;若被拒,拒绝文案可读);
3. `tool_eval` 立即返回 `run_id`,`running/` 里出现运行状态;
4. 评估结束后顶层 `<run_id>.json` 存在、`running/` 状态被清、结果 **`key == C15`**;
5. `research_status` 先显示「仍在运行」,后显示完整报告;
6. 试验账本只多出预期的行,链校验通过,无异常;尝试记录(`attempts.jsonl`)逐步齐全。

## 失败处理
- 流水线某一步失败 ⇒ 记录原因、修、**同一份预注册下重来**(算流水线故障,账本照记)。
- 不因策略表现不佳而重来或换想法。**只跑这一个想法,不调参。**
