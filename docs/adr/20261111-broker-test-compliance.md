# ADR: 国信程序化测试合规——阈值预警、暂停交易、证据与报告

- 状态:已采纳
- 日期:2026-11-11
- 跟踪:Issue [#8](https://github.com/laiyinyizao007/invest/issues/8)(功能缺口)、后续取证与报告生成另建 Issue
- 依据:国信期货《外部接入系统技术测试报告》模板(20251203 版):穿透式测试 + 程序化测试(六类 11 项,摘自中国期货业协会《期货程序化交易系统功能测试指引》)
- 实现:`trading/guard_rule.py`、`scripts/pause_trading.py`、`scripts/collect_terminal_info.py`、`scripts/penetration_check.py`

## 背景
国信要求程序化交易系统在测试环境里逐项演示并附截图。盘点 11 项后发现两处**功能**缺口(其余是"没有留下证据",由后续的取证与报告生成解决):

1. **3.1 阈值设置及预警**:vn.py 内置风控规则触达上限时只 `write_log("委托被拦截,…达到上限…")` 并拒单,不推任何通知;
   国信要求"指标达到或超过阈值后预警(弹窗/声音/短信/邮件等)"。
2. **5.1 暂停交易**:系统没有操作员可触发的暂停入口——只有熔断自动锁定与停进程。

## 决策

### 1. 阈值预警走既有告警通道
- `AccountGuardRule._on_log` 识别风控引擎自身的阈值日志(`gateway_name == APP_NAME`,前缀「委托被拦截,」且含「达到上限/超过上限」)→ 发 `WARN`「风控阈值触发」告警,
  经现有 Webhook(飞书/Telegram)送达,并因此进入日志文件,成为 6.1 日志要求里的**监测记录**。
- **按指标节流**(把数字去掉后的指标名为键,默认 300 秒):一个指标持续超限时每笔被拒都推一条会淹没真正的告警。
- 只认**笔数/手数/金额类**阈值;合约代码不存在、价位不是最小变动价位整数倍这类**校验失败**不属于阈值,不预警(它们仍是 4.1 指令检查的证据)。
- 预警方式的合规性:国信列的"弹窗/声音/短信/邮件"是"包括但不限于";Webhook(Telegram/飞书)即时消息属于同类的主动通知,**按用户判断算作预警方式**(2026-11-11);国信如有异议再补弹窗/邮件通道。
- **被否方案**:改 vnpy_riskmanager 源码(升级即失效);轮询规则计数(重复造轮子,且拿不到"被拒"事件)。

### 2. 暂停交易 = 标志文件,拒开仓、放行平仓
- `data/state/pause_trading.flag`(与状态文件同目录)存在时 `check_allowed` 拒绝**新开仓**,平仓与持仓管理照常——沿用「平仓永远放行」原则,暂停不能让持仓失去保护。
- `scripts/pause_trading.py on|off|status` 写/删标志;切换时发一次 `WARN` 告警(边沿触发)。
- **权限边界**:谁能写运行机上的这个文件,谁才能暂停;**不开远程入口**。远程控制(`/stop_all`)已在路线图登记为规划位,需要新 ADR 解决指令来源校验与误触问题。
- **被否方案**:停止进程(会让本地止损失效,与既有「硬锁定后进程保持存活直到确认空仓」的设计冲突);复用熔断锁(会写进账户状态文件、需要走解锁冷却流程,不适合"可随时恢复"的应急暂停)。

### 3. 其他
- `collect_terminal_info.py` 增加整机厂商/型号/内存字段(程序化测试报告「测试机型号/内存」栏复用)。
- **优雅登出**(`trading/graceful_exit.py::logout_ctp`):`vnpy_ctp` 网关的 `close()` 只调用 `exit()`——断开连接,**从不发登出请求**,
  而国信检查「登录后连接的会话数是否正确」「退出后是否正常注销」。现在运行时 `shutdown()`(先于 `main.close()`)与脚本共用的 `close_engine` 都会先向
  已登录的交易、行情通道各发一次 `ReqUserLogout`,再等 1.5 秒让前置处理。`TdApi/MdApi` 暴露了 `reqUserLogout`,但网关没有覆盖 `onRspUserLogout`,
  **拿不到登出回报**,所以只能"发请求+固定等待";登出任何一步失败都只记日志,不打断退出(尤其"退出时仍有持仓"的 FATAL 告警必须照常发出)。
- `close_engine` 返回是否在限时内关闭;`penetration_check` 在报告里记录「关闭连接」步骤。超时强杀(`os._exit`)可能比正常断开更糟,所以超时要如实写进报告。
- 登出请求是否真的让国信判定为"正常注销"仍要**测试时观察并回填本 ADR**(无回报可验证,只能看国信侧会话)。

### 4. 取证与报告生成(Issue [#9](https://github.com/laiyinyizao007/invest/issues/9))
国信要求**每次**(新版本、AppID 变更、模板更新)提交这份报告,所以做成可重复生成:
- `scripts/broker_test.py`(取证运行器)在**同一条真实测试连接**上挂载**真实的** `SafeRiskManagerApp`,按序演示 18 个测试项
  (穿透 T1–T7、程序化 P1.1–P6.1),每项产出 `Evidence`(状态 PASS/FAIL/SKIP/MANUAL + 若干 `Shot`),写入 `data/broker_test/<时间戳>/evidence.json`,
  并把脱敏后的证据文本用 Pillow 渲染成 `images/*.png`。状态完全隔离(`.vntrader_brokertest/`),不污染实盘的风控状态与日志。
  - 门禁同 `penetration_check`:`--confirm-broker-test`;只放行 `CTP_ENVIRONMENT=测试` 或 SimNow 预演;生产 API 无条件拒绝。
  - 4.1 指令检查**经风控链**发单(证明本地拦截);4.2 柜台错误**绕过本地风控**直发(采集真实柜台文本);
    3.1/T6 阈值与 2.3 重复报单把阈值临时调小、触发后还原;5.1 暂停用 `pause_trading` 的真实标志路径。
  - 依赖交易时段的项(成交、撤单阈值、「市场状态不允许」、行情)在不合适的时段标 `SKIP` 并说明,`--resume` 增量补测,**新的 SKIP 不覆盖旧的 PASS/FAIL**。
  - 2.1 连接断开监测**半自动**(`--interactive` 提示操作者断网/恢复,从网关日志读时间线);T7 异常自动退出用运行时退出语义的离线测试做**代码级验证**并如实标注。
  - 一次运行只登录一次、授权失败不重试(国信会检查频繁登录/大量错误登录);**所有会发单的测试项前统一过空仓闸门**(见 §5)。
- `scripts/broker_report.py`(报告生成器)用 **lxml 直接改国信原模板 docx**(不新增依赖,保留版式):以单元格文字定位行而不是写死下标;
  `set_checks` 处理 Wingdings 符号与字面 `□`,**先精确再前缀**匹配(勾「CTP」不会连带勾「CTPⅡ mini」);
  **绝不默认勾通过**——模板预勾选的结果一律重置,只有取证为 PASS 才勾,选测项未测勾「未测试」,必测项没通过则不勾「测试结论:通过」并列出"报告里还缺什么";
  **不碰国信填写区**(「信息科技中心评估」「测试人员(国信期货)」);签字/盖章栏留空,提示人工处理。
- **模板不入库**(含国信测试环境的 IP/端口,仓库可能公开):`--template` 或 `BROKER_REPORT_TEMPLATE` 传路径;测试里现场构造同结构的迷你模板。
  已用用户提供的真实模板做过一次填写,Word 能正常打开(导出 23 页 PDF);更新模板版本后需再用真模板验证。
- 开发中测试抓到一个真缺陷:「证明材料」标题自身含「测试系统功能测试指引」字样,首版边界判断把整个证据区切成了空——真实模板同样会触发。

### 5. 取证运行器的硬约束(codex 第二轮审查后固化)
取证脚本会**向柜台发真实委托**,所以它的行为约束和实盘运行时一样严格。以下几条是审查中发现并补上的,写在这里作为运行前提:

| 约束 | 为什么 | 表现 |
|---|---|---|
| **发单前统一过空仓闸门** | 「无仓位可平」「暂停期间平仓」这类演示单在账户有持仓时**会真的平掉仓位** | 所有会发单的测试项(穿透 T3/T4/T5、程序化 P1.2/P2.3/P3.1/T6/P4.2/P5.1)前先查持仓;有持仓或连接断开查不准 → 全部记 `FAIL`、**一笔不发**。`--only` 只跑某一项也过闸门 |
| **演示委托用唯一价格** | 重复报单规则的键是「合约+方向+开平+手数@价格」,不同步骤共用一个价格会落进同一个键,污染计数、让 2.3 的证据失真 | 每笔演示委托的价格上浮一个最小变动价位(循环 20 档,仍远低于市价);2.3 内部四笔仍同价(要素完全相同)才构成「重复」 |
| **白名单只能收窄,不能放宽** | 白名单(`BROKER_TEST_ALLOWED_TD/MD`)与 `CTP_TD_ADDRESS` 同源,采信它等于**自证清白**:把地址和白名单一起改成生产机就能放行 | 代码里写死「可信前置全集」(`ctp_tools/broker_targets.KNOWN_TD/KNOWN_MD` = 国信测试前置 + SimNow),白名单只能取它的**子集**;全集外的地址一律丢弃并告警。白名单为空 = 操作员没说清连哪台 → 拒绝连接,代码不替他决定 |
| **地址集与经纪商代码绑定** | 「可信全集」是国信 ∪ SimNow,**两个环境是不同的账户、不同的柜台**。白名单若能同时涵盖两者,「国信档案 + SimNow 前置」也能过闸 —— 清场按哪个账户连、取证按哪个账户连一旦不一致,平掉的就不是要取证的那个仓位 | `allowed_for_broker(broker_id)` / `resolve_allowed_for_broker(...)`:国信档只认国信前置,SimNow 档只认 SimNow 前置;未知 BrokerID → 两个空集(没有「默认放行」) |
| **档案解析只有一个入口,冲突分硬软两级** | 进程环境变量与档案不一致时,只能靠猜才能往下走 → 必须拒绝;但操作员**明说**了用哪个档案(指定 `--profile`),残留的进程环境变量只该提示,不该拦。不分流的话 `--profile .env.guoxin` 会被上一次运行的残留值永久挡住 | `ctp_tools/profile.py` 的 `load_profile()` → `Profile(env, hard_conflicts, notes)`:硬冲突 → 拒绝运行(退出码 2);软提示 → ⚠ 后继续。取证/穿透/探针/清场**全部**走它,不再各写一份 `dotenv_values` |
| **持仓按「本次查询回报」取,不读 OMS 快照** | vnpy_ctp 只在持仓查询回报 `last=True` 时推送**本次返回的**行(回报结束即清网关缓存);而 vn.py 的 `OmsEngine` **从不删除**条目 —— 平掉的仓位永远留在缓存里。按 OMS 快照判断空仓,平仓成功后仍会说「账户有持仓」,后面所有发单步骤都被闸门挡住 | `ctp_tools.collector.query_positions()` → `(rows, "ok"\|"empty"\|"untrusted")`;空仓闸门与清场都只认查询回报 |
| **清场收尾按成交量对账** | 「查询显示没有持仓」不等于「平掉了」—— 委托可能没成交,也可能成交在别的合约上 | 清场收尾把**初始持仓手数**与**实际成交量**逐合约对账:差额对不上 → 退出码非零并写明差额来历不明,不允许报「已平空」 |
| **取证运行器拒绝非国信环境** | 单独跑 `broker_test.py` 指向别的前置时,产出的证据仍写着「国信」—— 看上去像国信报告 | 非 `8030` 的经纪商代码必须显式加 `--rehearsal`;连接记录里写明 `mode`(guoxin / rehearsal),预演产出的报告不能交国信 |
| **测试环境地址仍需人工确认** | 测试版 API 与生产前置不通用握手,脚本**无法**用连接结果反推「连的是不是国信测试前置」 | 入口打印交易/行情前置地址,操作员必须人工核对;白名单只保证「不是已知的安全地址」,不保证「就是国信那台」 |
| **交易通道判活看 `login_status`** | vnpy_ctp 断线时**只清 `login_status`**(`connect_status` 一直是 True),用后者判活的话,断线后查询照样「成功」返回空持仓 | 空仓闸门与持仓查询的在线判定统一读 `login_status`(`ctp_tools.collector.trade_live`);**「查不到持仓」不等于「没有持仓」**:查不准一律判不可信(FAIL / 退出码 4),不放行发单 |
| **上期所/能源中心今昨仓拆不出来就拒绝自动平仓** | vnpy_ctp 只在**纯昨仓**时写 `yd_volume`,今昨混合仓拆出来的「平今手数」会超过实际今仓,柜台以「平今量超过今持仓量」拒单 | `split_is_reliable()` 判定不可靠 → 不生成平仓单,只提示人工平仓(平不掉比多让人工点两下危险得多) |
| **异常也要清场** | 演示中途抛异常会遗留暂停标志或挂单,下一轮运行就带着脏状态 | 暂停步骤 try/finally:无论成败都解除暂停标志并撤掉遗留委托;阈值步骤无论成败都还原阈值 |
| **撤单要等确认终态** | 撤单请求发出不等于撤成功,拿不到终态就报「撤单数达到阈值」是虚报 | 等终态为 `CANCELLED` 才计入撤单计数,否则证据写 ⚠ 并说明终态;收尾兜底撤单同样等终态,超时的单独列出来 |
| **日志只取本次运行** | 同一天多次运行共用一个日志文件,旧行混进证据会让截图看起来像别的操作 | 按本次运行开始时刻截取,无时间戳的续行跟随其前一行 |
| **一次运行只登录一次** | 国信会检查频繁登录/大量错误登录 | 每轮运行登录一次后复用同一连接;**例外**:3.1 连接断开监测需要断网再恢复,用 `--resume` **另起一轮**补测(那是两轮各登录一次,不是一轮里登两次) |

报告侧同批补的两条:
- **选测项未通过也不勾「测试结论:通过」**——结论只认全部必测项通过且没有选测项 `FAIL`;选测 `FAIL` 时在「报告里还缺什么」里点名要人工判断。
- **证据图文件缺失要显式报出**——`evidence.json` 里登记了图、磁盘上文件没了,报告里插不了图,但必须进 warnings 与缺失清单,不能静默跳过(否则会交一份缺图的报告)。

## 已知局限
- 5.2 **批量撤单(选测)暂不做**:报告里标「未测试」,登记在 `docs/roadmap.md` §2.6。
- 2.1 连接断开监测的**全自动断网演练**未做:取证时半自动(提示操作者断网/恢复),登记在路线图。
- "截图"是**证据文本渲染成的图片**,不是真实界面截图:内容取自真实运行的脱敏日志与计数,可追溯;**是否被国信接受需确认**(不接受时改为在运行机上手工截屏替换)。
- 渲染需要中文字体(默认 `msyh.ttc`);找不到会告警,中文显示为方框,可用 `BROKER_REPORT_FONT` 指定。
- 报告里的**测试账号写全**(表单要求,只给国信看),控制台与日志仍脱敏;签字/盖章必须人工完成。
- 暂停标志只影响**开仓**;平仓、止损、紧急平仓不受影响(这是有意的)。

## 修订(2026-11-12,Issue [#14](https://github.com/laiyinyizao007/invest/issues/14)):适配 20260717 版模板
客户经理重发资料后,新模板与本 ADR 依据的 20251203 版结构不同:
