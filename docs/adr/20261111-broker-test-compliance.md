# ADR: 国信程序化测试合规——阈值预警、暂停交易、证据与报告

- 状态:已采纳
- 日期:2026-11-11
- 跟踪:Issue [#8](https://github.com/laiyinyizao007/invest/issues/8)(功能缺口)、后续取证与报告生成另建 Issue
- 依据:国信期货《外部接入系统技术测试报告》模板(20251203 版):穿透式测试 + 程序化测试(六类 11 项,摘自中国期货业协会《期货程序化交易系统功能测试指引》)
- 实现:`trading/guard_rule.py`、`scripts/pause_trading.py`、`scripts/collect_terminal_info.py`、`scripts/penetration_check.py`

## 背景
国信要求程序化交易系统在测试环境里逐项演示并附截图。盘点 11 项后发现两处**功能**缺口(其余是"没有留下证据",由后续的取证与报告生成解决):

1. **3.1 阈值设置及预警**:vn.py 内置风控规则触达上限时只 `write_log("委托被拦截,…达到上限…")` 并拒单,不推任何通知;
   国信要求"指标达到或超过阈值后预警(弹窗/声音/短信/邮件等)"。
2. **5.1 暂停交易**:系统没有操作员可触发的暂停入口——只有熔断自动锁定与停进程。

## 决策

### 1. 阈值预警走既有告警通道
- `AccountGuardRule._on_log` 识别风控引擎自身的阈值日志(`gateway_name == APP_NAME`,前缀「委托被拦截,」且含「达到上限/超过上限」)→ 发 `WARN`「风控阈值触发」告警,
  经现有 Webhook(飞书/Telegram)送达,并因此进入日志文件,成为 6.1 日志要求里的**监测记录**。
- **按指标节流**(把数字去掉后的指标名为键,默认 300 秒):一个指标持续超限时每笔被拒都推一条会淹没真正的告警。
- 只认**笔数/手数/金额类**阈值;合约代码不存在、价位不是最小变动价位整数倍这类**校验失败**不属于阈值,不预警(它们仍是 4.1 指令检查的证据)。
- 预警方式的合规性:国信列的"弹窗/声音/短信/邮件"是"包括但不限于";Webhook(Telegram/飞书)即时消息属于同类的主动通知,**按用户判断算作预警方式**(2026-11-11);国信如有异议再补弹窗/邮件通道。
- **被否方案**:改 vnpy_riskmanager 源码(升级即失效);轮询规则计数(重复造轮子,且拿不到"被拒"事件)。

### 2. 暂停交易 = 标志文件,拒开仓、放行平仓
- `data/state/pause_trading.flag`(与状态文件同目录)存在时 `check_allowed` 拒绝**新开仓**,平仓与持仓管理照常——沿用「平仓永远放行」原则,暂停不能让持仓失去保护。
- `scripts/pause_trading.py on|off|status` 写/删标志;切换时发一次 `WARN` 告警(边沿触发)。
- **权限边界**:谁能写运行机上的这个文件,谁才能暂停;**不开远程入口**。远程控制(`/stop_all`)已在路线图登记为规划位,需要新 ADR 解决指令来源校验与误触问题。
- **被否方案**:停止进程(会让本地止损失效,与既有「硬锁定后进程保持存活直到确认空仓」的设计冲突);复用熔断锁(会写进账户状态文件、需要走解锁冷却流程,不适合"可随时恢复"的应急暂停)。

### 3. 其他
- `collect_terminal_info.py` 增加整机厂商/型号/内存字段(程序化测试报告「测试机型号/内存」栏复用)。
- **优雅登出**(`trading/graceful_exit.py::logout_ctp`):`vnpy_ctp` 网关的 `close()` 只调用 `exit()`——断开连接,**从不发登出请求**,
  而国信检查「登录后连接的会话数是否正确」「退出后是否正常注销」。现在运行时 `shutdown()`(先于 `main.close()`)与脚本共用的 `close_engine` 都会先向
  已登录的交易、行情通道各发一次 `ReqUserLogout`,再等 1.5 秒让前置处理。`TdApi/MdApi` 暴露了 `reqUserLogout`,但网关没有覆盖 `onRspUserLogout`,
  **拿不到登出回报**,所以只能"发请求+固定等待";登出任何一步失败都只记日志,不打断退出(尤其"退出时仍有持仓"的 FATAL 告警必须照常发出)。
- `close_engine` 返回是否在限时内关闭;`penetration_check` 在报告里记录「关闭连接」步骤。超时强杀(`os._exit`)可能比正常断开更糟,所以超时要如实写进报告。
- 登出请求是否真的让国信判定为"正常注销"仍要**测试时观察并回填本 ADR**(无回报可验证,只能看国信侧会话)。

## 已知局限
- 5.2 **批量撤单(选测)暂不做**:报告里标「未测试」,登记在 `docs/roadmap.md` §2.6。
- 2.1 连接断开监测的**全自动断网演练**未做:取证时半自动(提示操作者断网/恢复),登记在路线图。
- 后续生成的"截图"是**证据文本渲染成的图片**,不是真实界面截图:内容取自真实运行的脱敏日志与计数,可追溯;是否被国信接受需确认。
- 暂停标志只影响**开仓**;平仓、止损、紧急平仓不受影响(这是有意的)。

## 验证
`tests/test_broker_compliance.py`:阈值触达→WARN 告警且同指标节流、不同指标分别告警、节流过期、校验失败不预警;暂停→开仓被拒/平仓放行/恢复、告警边沿触发;`pause_trading.py` 三个子命令;整机字段。
