- 状态:已采纳(2026-11-13 用户同意『变异输入与适应度』方案中的结构化反馈、质量多样性、不回灌;PBO 与 DSR 已裁决:**都先不做**,见第 1 条)
- 日期:2026-11-13
- 跟踪:Issue [#1](https://github.com/laiyinyizao007/invest/issues/1)
- 关联 ADR:`20261110-bisheng-ai-researcher.md`(外层 AI 研究员用毕昇编排)、`20261112-status-dashboard.md`(只读状态页)、
  `20261112-research-sandbox-config-and-approval.md`(提交与批准)、`20261111-risk-floor-immutability.md`(风控底线与「明确不做」)

## 背景

用户要三个面板来看「AI 策略进化」的过程:**进化曲线**(每代夏普与收益的成长趋势)、**参数热力图**(参数敏感度,识别稳健高原与过拟合孤岛)、
**代码与变异日志**(正在跑/被淘汰的代码、反思意见、代码差异)。同时要求:**能用毕昇的就用毕昇,让过程可视化**。

现状核对(2026-11-13):

| 需要的数据 | 现状 |
|---|---|
| 参数热力图 | **目前没有落盘**。`select_params` 的返回里有 `plateau.scores`(三维网格得分),但 `run_evaluation` 保存结果时只留摘要(`n_cells / valid_cells / on_plateau / plateau_cell`),完整得分表被有意留在服务端、不回传给外层(`scripts/research_gate.py`)。(2026-11-13 更正:本 ADR 初稿曾误写『已有』。) |
| 进化曲线(代、种群统计) | **没有**。没有「代」「父代」的记录,网关只记 `submissions.jsonl`(额度账本) |
| 反思意见、代码差异 | **没有**。反思文本只存在于毕昇工作流的运行上下文里;候选代码在 `pending_strategies/`,但无父子关系 |
| 自动进化回路 | **没有**。毕昇 v3 是单轮「想法→候选→评估」,`--rounds` 只用于联调 |

## 决策

### 1. 分工:毕昇负责「跑」,状态页负责「看结果」
- **进化回路由毕昇工作流承载**(新增 v4:生成一代 → 提交 → 本机批准 → 选参+门槛评估 → 反思节点产出修复意见 → 下一代),**不在仓库里另写一套循环**。
  工作流自身的节点运行状态、每一步输入输出,直接用**毕昇界面**观看——这是过程可视化的第一层,零开发。
- **状态页只读展示沉淀下来的结果**(曲线、热力图、日志、代码差异)——这是第二层,面向「长期趋势与审计」,不依赖毕昇是否在线。
  毕昇宕机时,历史仍可看;状态页不触发、不暂停、不调整任何进化动作。
- 「TextGrad」在这里只是**反思文本的展示名**:反思由毕昇里的 LLM 节点产生,仓库与状态页都不执行任何梯度或自动改码逻辑。

### 2. 谱系记录:网关追加写,面板只读
- 网关(研究侧进程)在提交与评估时追加写 `data/research/evolution/<campaign_id>.jsonl`,每行一条记录:
  `campaign_id, generation, candidate_sha256, parent_sha256, run_id, status, sharpe, total_return, max_drawdown, dsr, n_trials, fail_reason, reflection, created_at`(`dsr`、`n_trials` 同样由网关从评估结果 `metrics` 取,经与引擎会话协调后追加)。
- **分工**:台账的写入由进化引擎计划(`docs/adr/20261113-evolution-engine.md`,在分支 `feat/15-trial-ledger-dsr`)的阶段 3 按本格式实现;状态页后端只做**读取侧**与示例数据,本 ADR 不修改网关。`data/research/trials.jsonl` 是试验次数账本(kind/count/at),**不是代数数据,面板不读取**。
- 毕昇工作流在提交请求里带可选字段 `campaign_id / generation / parent_sha256 / reflection`。这些字段**不影响任何选参、评估或批准**
  (请求体里不接受影响选参的字段这条约束不变);只是被记录。
- **数值字段(夏普、收益、回撤)由网关从评估结果取,不采信调用方声明**——曲线上的数字不能由 LLM 自报。
- `reflection` 是**不可信的 LLM 文本**:限长(2KB)、仅存储与展示、展示前过 `dashboard/safe.py`、**绝不回灌进任何 LLM 上下文**。
  这与既有「硬记忆预算」一致:外层反馈仍只携带最近 3 次失败的结构化 Trace,谱系台账**只用于人看**,不是 LLM 的记忆。
- 面板对 `data/research/evolution/` 与 `pending_strategies/` 只读;代码与差异在服务端按哈希读取、`difflib` 生成,大小有上限,按纯文本返回。

### 2b. 热力图数据需要落盘(待引擎侧实现)
评估时把完整得分表另存为 `data/research/heatmaps/<run_id>.json`(`axes`、`scores`、`best_cell`、`on_plateau`),**不并入网关返回给外层的响应**——『得分表不给 LLM 看』这条保持;面板只读该文件给人看。写入属引擎侧(`research_api` / `research_gate`)改动,已转告引擎会话,本会话不修改。

引擎会话已同意该落盘格式(`axes`、`scores`、`best_cell`、`on_plateau`;无效格用字符串 `"-inf"`),计入其阶段 3,阶段 3 要等用户对 PBO 硬条件与 DSR 选父代表态后才开工,所以该文件目前不存在,读取侧按 `missing` 处理。
**展示约束**:热力图的分数来自**选参窗口**,不是验证窗口;面板与前端文档必须标注『选参窗口得分』,不得被读成样本外表现。

### 2d. 战役摘要的缓存(读多写少的场景)

总览每 8 秒轮询一次,而战役台账可能很大(上限 50 个战役 × 8 MB)。所以摘要要缓存:

- **两个缓存**:`_EVOLUTION_SUMMARY_CACHE`((路径, 内容哈希) → 摘要)与 `_EVOLUTION_TTL_CACHE`(路径 → {at, summary})。
  **两类键必须分开计数**——混在一个 dict 里时每个战役占两个条目,有效容量只剩一半,而淘汰又是清空,
  于是越过一半上限后缓存对大部分部署形同虚设(总览每轮重读全部台账)。
- **键用内容哈希,不用元数据**:同长度改写并恢复 mtime 后,元数据看不出来,哈希能。
- **TTL 兜底**:算哈希也要读完整个文件,所以再加一层短 TTL(默认 30 秒,配置项 `evolution.summary_ttl`):
  TTL 内直接用缓存,过期后强制重算——『同长度改写』最多藏一个 TTL 的时间。
- **损坏的台账也要进缓存**:否则每个请求都会重读并重新哈希整个文件。
- **启动时预热**(`warm_up`):否则冷启动后第一个总览请求要十几秒。
- **逐出最旧的,不清空**:一次统计的战役数(50)必须小于缓存上限。

### 3. 服务端算好,前端只渲染
- 曲线:每代 `elite / mean / p25 / p75`(夏普)与收益、回撤;提示标志 `stagnant`(连续 N 代精英无提升,默认 5)与 `overfit_suspect`(精英与种群均值差距超阈值)。
  阈值放配置,文案是「提示」而非「结论」。**标志由服务端给,前端不重算。**
- 热力图:服务端把三维网格切成二维(第三轴取 `best_cell`),`-inf` 单元显式标为「无效」(不画成 0);「平原/孤岛」沿用候选评估已有的 `on_plateau`,面板不另立判定规则。
- 状态语义沿用核心原则:无战役 = `missing`;台账损坏/时间在未来 = `corrupt`;久无新代 = `stale`;可选子系统不计入总体级别。

### 4. 明确不做(写死,防止被反复重提)
| 事项 | 理由 |
|---|---|
| 面板上的「注入随机突变」「调整种群」「淘汰/晋级」「回滚」按钮 | 越过只读边界;批准永远是本机人工动作(`20261112-research-sandbox-config-and-approval.md`) |
| 无人值守的连续进化(毕昇 4c) | 仍以容器级隔离为硬前置(`20261112-bisheng-integration-spec.md` §四);在此之前,进化每一代仍需人工批准才能评估 |
| 让大模型自报的夏普/收益进入曲线 | 数字必须来自沙盒评估结果 |
| 把反思文本或谱系回灌给 LLM | 提示注入面 + 违反硬记忆预算 |
| 用曲线上的高分直接放行晋级 | 晋级仍只认 `promotion_gate` 与人工批准;曲线是观察窗口,不是闸门 |

### 2c. 启用与阈值(配置层)

面板侧的配置在 `config/status_dashboard.json`:

```json
{
  "evolution": {
    "enabled": false,          // 阶段④上线时才置 true:为真才注册那 6 个接口(与阶段②-⑤ 的既有约定一致)
    "stagnant_generations": 5, // 连续多少代没提升算『停滞』
    "stagnant_epsilon": 0.05,  // 允许的微小提升(夏普)
    "overfit_mean_gap": 1.0,   // 精英夏普与种群均值差多少算『过拟合嫌疑』(只是提示)
    "log_limit": 50            // 变异日志的默认页大小与上限
  }
}
```

其余的资源上限(都在代码里,不暴露给前端):台账单个文件 8 MB、总行数 20 万、有效记录 2 万条;
热力图文件 4 MB、格子 20 万;候选源码 256 KB;一次最多统计 50 个战役(超出的如实说明『未统计』)。

这些阈值是**经验默认值,不是统计结论**;文案里必须写明是提示。目录位置(`evolution_dir` / `heatmap_dir`)
也在同一层配置,默认 `data/research/evolution` 与 `data/research/heatmaps`。

## 变异输入与适应度:用户裁决(2026-11-13)

引擎计划想把精英档案/父代码回给 LLM,与『硬记忆预算』和『台账只给人看』冲突。裁决:**不放宽记忆预算,改用下列做法**(方法来自 FunSearch / AlphaEvolve 的评估器打分、MAP-Elites 质量多样性、DSR/PBO 多重检验校正、dual-LLM 隔离思路;**未联网逐项核实细节,落地前由引擎会话在其 ADR 里确认**):

1. **适应度只信评估器**:数字来自沙盒评估,不采信大模型自报。(已定)
   **PBO 与 DSR:用户裁决(2026-11-13)——两项都先不做,选父代只用选参窗口的适应度。**
   - **不用 DSR 选父代**:`dsr` 由验证窗口的结果算出。用它决定『谁当父代』,等于每一代都拿验证窗口的成绩做选择;
     进化几十代后种群会逐渐适应验证窗口的特点,验证窗口就从『考试』变成了『练习』,不再是独立检验——这正是过拟合,只是藏得更深。
     引擎的分层原则:选参窗口的反馈放开,验证窗口的反馈限量,最终留出集永不进回路。`dsr` 与 `n_trials` 仍照常记录和展示给人看,只是**不参与选择**。
   - **不把 PBO 作晋级硬条件**:PBO(回测过拟合概率)需要足够多组独立的训练/测试划分。现有复权 15 分钟数据只有玉米一个品种、3 个滚动窗口,
     估计误差大于它要检测的信号。把噪声很大的数字当硬条件,既可能随机挡掉合格策略,也可能随机放过不合格的策略,
     还会给人『已做过过拟合检验』的错觉——与本项目『不制造虚假安心』的原则相反。引擎 ADR 已采纳『PBO 延后』,此处与之一致。
   - **重新评估的条件**:(a) 扩充到多个品种的复权连续合约数据(其他 DCE 品种目前只有原始分钟线,数据来源与跨度未核实),
     且能给出 PBO 估计的置信区间;(b) 或者验证窗口之外另有从不进入回路的独立留出集可供检验。满足之前不重提。
   - **代价**:不用 DSR 选择,意味着选参窗口内的过拟合只能靠质量多样性、结构化反馈、候选评估的既有门槛(含参数高原)来约束,
     没有『多重检验校正』这一层。这是已知的缺口,不是遗漏。
2. **质量多样性(简化版,已定)**:种群按行为特征分格(如持仓周期、交易频率),每格只留最好的一个;格子数从小做起(单品种约 5.9 年分钟线,格太细则每格样本不足)。加权只用于『同一格内选谁当父代』。
3. **反思节点输出结构化结果(已定)**:只允许预先定义的字段(失败类型枚举、涉及指标、建议修改方向枚举、0–1 数值),由程序校验,不合格丢弃。**自由文本反思只存档给人看,不进入变异提示词。**
4. **父代码不原样回灌(已定)**:回灌的是程序从代码中抽取的可验证描述(用了哪些指标、入场条件个数、参数所在网格单元)。
5. 变异输入仍受『最近 3 条结构化 Trace』预算约束。

对状态页的影响:曲线与日志增加『格子』维度与『父代所在格子』、结构化诊断;反思自由文本仍展示但标注『仅供审阅,未进入模型输入』。以上主要是引擎侧设计,属 `20261113-evolution-engine.md` 的范围。
