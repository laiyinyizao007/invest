## 背景:两条规则互相打架

晋级门槛里有两条都管「样本外夏普」:

- 第 1 条:**夏普 < 1.5 不通过**;**夏普 > 3.0 也不通过**(报「先排查前视偏差/过拟合」)。
- 第 9 条(`20261113-evolution-engine` 锁定):**DSR ≥ 0.95**。

DSR(Bailey & López de Prado)是**去通胀**判据:在 N 次试验里挑出的最优夏普,
要扣掉「纯靠运气能挑到多高」那部分(`SR0(N,T)`)。**N 越大,这个运气基准越高。**

⇒ 同一个年化夏普,在 N 大时**能**通过 DSR、在 N 小时**不能**。
⇒ 而那条写死的 **3.0 上限与 N 无关** ⇒ **N 大时,一个 DSR 认证过的候选会被那条固定上限
**先一步**毙掉**,报出来的是「先排查前视偏差」——而 DSR 那一关**根本没走**。

这正是用户裁决要解决的问题(2026-11-17):**放宽 `max_suspicious_sharpe`,直到与 DSR 自洽**。

## 决策

「样本外夏普高得可疑」的上限不再是一个与试验次数无关的常数,而是:

```
上限(N, T) = max( 3.0 , 年化(认证线(N, T)) )
认证线(N, T) = DSR 恰好等于 min_dsr(0.95) 的那个**日**夏普
```

- **认证线**由 `risk/dsr.py::required_sharpe_for_dsr` 给出:正态收益假设(偏度 0、峰度 3)
  下 `DSR(sr) = Φ( (sr − SR0(N,T))·√(T−1) / √(1 + sr²/2) )`,解 `DSR(sr) = min_dsr` 得闭式解:

  ```
  u2 = T−1 ,  q = Φ⁻¹(min_dsr) ,  A = u2 − q²/2
  sr = ( SR0·u2 + q·√( SR0²·u2/2 + A ) ) / A
  ```

  (取大根;小根落在 `sr < SR0` 处,那里 DSR < 0.5。)闭式解与数值反解在 48 组 (N,T) 上**零不一致**。
- **兜底下限 3.0 保留**(字段改名 `suspicious_sharpe_floor`)⇒ 任何 (N, T) 下限值 **≥ 3.0**
  ⇒ **只放宽、不收紧**:旧规则放行的候选,新规则一个都不会被毙掉。
- **DSR 阈值 0.95 不动**(`min_dsr` 未改),DSR 仍**不用于父代选择**。
- 退化输入(N 缺失、样本太短、解不出来)⇒ 落回兜底 3.0(fail-closed:解不出来不得用来放宽)。

> **第 55 轮之十七更正(codex 双轮复核)**：「认证线按**正态收益**假设反解」这句话
> **不能**被读成「正态假设偏保守 ⇒ 全局安全」。正态假设**两侧的偏向不同**,
> 判断口径是「DSR 关的**有效下限**落在哪」:
>
> - **正偏度一侧(不保守)**：实测分母 `denom = 1 − 偏度·sr + (峰度−1)·sr²/4`
>   被压到 1 以下 ⇒ 实测 DSR **高于**同夏普的正态值 ⇒ 实测下限**低于** 3.1121
>   ⇒ 正态假设在这一侧**偏严**(会把本可通过 DSR 的候选毙掉)
>   ⇒ 那正是本次改动打开的那一格。
> - **负偏度 / 厚尾一侧(保守)**：实测分母 **≥ 1** ⇒ 实测 DSR **低于**同夏普的正态值
>   ⇒ 实测下限**高于** 3.1121(甚至因为上限卡在 3.1121 而永远够不到)
>   ⇒ 正态假设在这一侧**偏松**(保守)⇒ 那一侧仍然安全。
>
> 精确判据(可自行验算,日夏普 sr > 0)：实测分母 < 正态分母 1
> ⟷ `偏度 > (峰度−1)·sr/4` ⇒ **偏度必须为正、且大到足以抵消峰度项**,
> 才可能比正态更宽松。真正的下界永远是 **DSR ≥ 0.95 那一关**,
> 而它用的是**样本自己的**偏度/峰度(`risk/dsr.py::deflated_sharpe`)。
> ⇒ **DSR 不是前视检测器**:它按矩去通胀,不识别前视。

**这张表要连着 CI 那条一起读**:夏普 95% 区间下界 > 0 要求样本外年数
`> z²(1 + SR²/2)/SR²`(SR = 3.0 时约 2.34 年 ⇒ T ≳ 562)⇒ **T 越大,认证线越低**
⇒ 在 T = 600 一列,N ≤ 500 时认证线还够不到 3.0 ⇒ **兜底生效 ⇒ 与旧规则判得一模一样**。
⇒ **放宽真正生效的区域是「N 大、样本外不太长」**。

## 诚实的结论:实际影响比想象中小,但比本文件初稿写的大一点(必须写明,不许写得比实测更好)

**第 55 轮之十七更正**:本文件初稿写的「放宽打开的窗口宽约 **0.011**」是**错的**
(错在把「正态模型内的子区间」当成了「这次改动打开的区间」)。两个数字都要写:

| 口径 | 数字 | 含义 |
|---|---|---|
| **这次改动实际打开的区间** | (旧上限 3.0, 新上限] ⇒ 宽约 **0.1121** | 旧规则毙掉的候选,新规则**不再**因为「可疑」而毙掉的部分 |
| 正态模型内的子区间 | **不存在**(宽 ≈ 0) | 正态矩候选的 DSR 在 (3.0, 上限] 内**全部 < 0.95**(实测 3.0→0.9293、上限→0.9500)⇒ **正态矩候选一个都落不进来**;落进来的必须偏度为正 |

⇒ 能否落进 (3.0, 3.1121] 取决于**候选自己的矩**:矩接近正态时**一个都落不进来**
(**第 55 轮之十九更正**:早先写的「正态模型内子区间 3.1013–3.1121、宽 0.0108」是**错的**——
那个数出自一个**忽略 DSR 分母 √(1+sr²/2)** 的近似式;按真正的 DSR 公式,
**正态认证线恰好等于上限本身** ⇒ 子区间宽度 ≈ 0);
**右偏**(偏度为正)的候选可以把实测 DSR 顶得更高 ⇒ 实测有一条 T=600、N=1000 的右偏序列:
年化夏普 **3.058191**、偏度 **7.180817**、峰度 **52.564130**、DSR 分母 **0.084817**、
实测 DSR **0.99999997** ⇒ **通过全部 `check_gate`**,
而旧规则(固定 3.0)会把它毙掉。

⇒ 结论有三条,都写在这里:

1. **不收紧(可证)**:上限 ≥ 3.0 恒成立 ⇒ 旧规则放行的候选一个都不会被毙掉。
2. **放宽比初稿写的大,但仍然只影响「N 大、样本外不太长」那一小片**:
   实际打开区间宽约 0.11 年化夏普;能落进去的候选其收益必须**右偏**(偏度为正)。
   ⇒ **这条改动不改变绝大多数候选的判定结果**。
3. **它的主要价值是口径统一**:上限不再是「与 N 无关的魔法数字」,而是 DSR 判据的另一面;
   诊断层(`risk/diagnosis.py`)报出来的上限随之 N 化 ⇒ **同一个问题只有一个答案**。

**明写一句(不许只讲加固那一面)**:这次改动**确实让某个夏普区间更容易通过**——
落在 (3.0, 3.1121] 且 DSR ≥ 0.95 的候选,旧规则会因「高得可疑」被毙掉,新规则放行。
这是**本轮有意为之**的放宽(用户裁决:「放宽 `max_suspicious_sharpe` 到与 DSR 自洽」),
按仓库 §4.8 总则「凡是让防线更松的改动一律按执行域处理」——本轮**全程按执行域走**
(结构化确认块、6/6 完备性清单、ADR 记录、codex 双轮复核、ADR 修订记录)。

**为什么不在认证线之上再加一个余量**(例如 `上限 = 认证线 + 1.0`)?那才真的能放宽,
但它会往晋级门槛里塞进**第二个没有统计依据的数字**——这正是本仓库 ADR 制度要防的事
(阈值须在看到候选之前有依据)。⇒ **本轮不做**;若将来要放宽到「认证线之上」,
须另立 ADR,给出该余量的统计依据与实测影响,而不是顺手加一个常数。

## 修订:第 55 轮之十七 —— codex 双轮复核后的更正与加固

codex 第 2 轮(执行域复核)给出 **42/50 ⇒ 需小修**,三条发现**本地全部复现**后才动手:

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| 1 | High | 「窗口宽约 0.011」与「正态假设偏保守 ⇒ 安全」**都不是全局结论**(正偏度会让 DSR 分母 < 1) | 文档与 docstring **按实测更正**(见上表与「更正」框);并补一条**非正态矩**探针(右偏 ⇒ 实测 DSR 0.99999997 ⇒ 过;同样夏普、正态矩 ⇒ DSR 顶不到 0.95 ⇒ 毙) |
| 2 | Medium | `oos_years = 1e308` ⇒ 折算溢出成 inf ⇒ `int()` 抛 **OverflowError**,门槛整个炸掉(不是 fail-closed) | 折算前先判有限;异常输入按「样本太短」处理 ⇒ 上限落回兜底 3.0 |
| 3 | Medium(预存,非本次引入) | `oos_harpe = NaN` / `oos_years = inf` ⇒ 与任何数比较恒为 False ⇒ **`check_gate` 返回空列表 = 全部通过** | 门槛**逐个字段**做合法性校验(有限数 / 布尔),非法一律不予通过 |
| 4 | Low | `suspicious_sharpe_floor = NaN` ⇒ 上限变 NaN ⇒ 「夏普 > 上限」恒为 False ⇒ 「可疑」这条**静默失效** | 兜底下限非法 ⇒ 退回常量 3.0 |

**第 3 条扩到了全部门槛字段**:原来只查 `oos_sharpe` / `oos_years` 是**半条规则** ——
回撤%、回撤元、往返笔数、随机分位、成本翻倍夏普在 NaN 下**同样**会被静默放过。
现在**七个数值字段 + 两个布尔字段**逐个查;布尔只认 `bool` / `0` / `1`
(字符串 `"False"` 在 Python 里是**真**,宽松真值判断会把该拦的放过去)。

**顺带加了一条物理上界**:`MAX_OOS_YEARS = 50.0`(现有 15 分钟数据自 2010 年前后开始,
50 年是任何现实数据集都够不到的数)。它**排除不可能的输入**(例如手改的指标文件写
`oos_years = 1e308` ⇒ 置信区间检查被架空成恒真)⇒ 只会让门槛**更严**,不会更松
⇒ 不违反「阈值须在看到候选之前有依据」。

**诊断层同款加固**(`risk/diagnosis.py`):诊断是门槛的「同一个问题的第二个答案」,
所以同一类缺陷必须一起修——`_num` 只取**有限数**(NaN/inf/超大 int ⇒ 报「未知」,
不许静默当成「没超限」);`oos_years` 折算溢出同样按「样本太短」处理 ⇒ 诊断不再被
`int(round(inf × 240))` 的 OverflowError 炸掉。

**残余(如实)**:门槛阈值全部可由 `GateThresholds` 覆盖。**阈值本身**若被传成 NaN,
本轮**一并加固**了(退回该字段的默认值)——理由与指标字段完全一样:`夏普 < NaN` 恒为
False ⇒ 下限那条**永远不触发** ⇒ 等于把这一关悄悄关掉。
尚未加固的:阈值**被换成别的有限值**时仍然是「生效的」(例如把 `min_dsr` 改成 0.5)——
这不是 bug,是 `GateThresholds` 的用途(阈值可调,但**调整须在看到候选之前确定并记录**,
见 `20261109-promotion-gate.md` 的影响一节);本轮不为此加锁。

另有一处**口径分叉**,本轮(codex 第 2 轮 High)**已统一**:第 55 轮之十七时
`suspicious_sharpe_cap` 反解认证线用的是**未净化的** `t.min_dsr`,而 `check_gate` 判定 DSR 用的是**净化后**的 `min_dsr`
⇒ 上限按一个阈值算、DSR 按另一个阈值判。现在两处都用**同一份**归一化值
`_normalized_min_dsr(t)`(非法 ⇒ 退回默认 0.95)⇒ **同一个问题只有一个答案**。

**这次统一本身带来一次放宽,如实记录**:阈值**非法**时(例如 `min_dsr = 0.0`),
上限从「落回兜底 3.0」变成「按默认 0.95 反解出的认证线」(N=1000、T=600 ⇒ 3.1121)
⇒ 在**阈值被配错**这个分支上,上限被放宽了。但同一个分支里 DSR 关
从「`dsr < 0.0` 恒为 False ⇒ **整关放空**」变成「按 0.95 判定」⇒
**旧行为是 fail-open(任何 DSR 都过)**,新行为是 fail-closed ⇒ 净效果是**收紧**。
⇒ 这是一次「把分叉收成一条」的改动,只影响阈值配错的分支;按仓库 §4.8 总则,
本分支**全程按执行域**处理(已在 ADR 记录 + codex 双轮复核)。
