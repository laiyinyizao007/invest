# ADR: Walk-Forward 滚动优化器(测试段隔离的时序切分网格寻优)

- 日期:2026-11-10
- 状态:已确定,方法学部分在看到任何滚动窗口结果之前写定
- 相关:`20261110-baseline-15m.md`、`20261109-negative-backtest-result.md`、`20261109-promotion-gate.md`

## 背景

15 分钟基准的单窗口实验(ADR `20261110-baseline-15m`)结论为无可延续的优势,且其测试段
(2024-01 ~ 2026-06)已被消费一次。继续研究需要一种**不触碰测试段**的选参方法:
Walk-Forward(滚动窗口)把 2020-07 ~ 2023-12 的可用区间切成多组"训练段 + 验证段",
每组只在训练段选参、在紧随其后的验证段做样本外检验,用多个独立验证段上的表现分布
代替单次切分的运气成分。

本 ADR 记录 `scripts/walk_forward_optimizer.py` 的方法学约束;脚本与本 ADR 同一原子提交。

## 决策一:窗口方案 — 训练 24 个月 / 验证 6 个月 / 步长 6 个月

| 窗口 | 训练段 | 验证段 |
|---|---|---|
| W1 | 2020-07-22 ~ 2022-06-30 | 2022-07-01 ~ 2022-12-31 |
| W2 | 2021-01-01 ~ 2022-12-31 | 2023-01-01 ~ 2023-06-30 |
| W3 | 2021-07-01 ~ 2023-06-30 | 2023-07-01 ~ 2023-12-31 |

- 三个验证段互不重叠、各自严格晚于本窗口训练段,杜绝未来函数;训练段跨窗口重叠是
  Walk-Forward 的正常形态,不构成信息泄漏(选参只读本窗口训练段);
- 所有窗口结束日 ≤ 2023-12-31,与测试段之间没有灰色地带;
- 每段回放从该段第一根 K 线开始,前 `slow_window + 19` 根只热身不交易(策略既有行为);
- 成交笔数(开+平)少于 100 的组合不参与排名;达标组合不足 5 个时窗口标记 `INSUFFICIENT`
  并如实报告,不凑数、不放宽门槛、不回头改窗口。

## 决策二:网格只扫 fast/slow 两维,atr_mult 与 risk_budget 固定

- `fast_window ∈ {10, 14, 18, 22, 26, 30}`、`slow_window ∈ {40, 50, 60, 70, 80, 90}`,
  保留 `slow >= 2 × fast` 过滤,共 31 组;
- `atr_mult` 固定策略类默认 1.5,不进网格:把检验对象收敛为"均线快慢"这一个假设,
  同时压低多重检验面;固定值与类默认一致,结果可与基线直接对照;
- `risk_budget=300` 是策略类默认(`TrendAtrStrategy`),参数字典里**不传该键**,
  因此没有任何代码路径可以覆盖它;每次回测输出 `skipped_by_budget` 与弃单率
  (`skipped / (skipped + 往返笔数)`),高波动期"无法交易"与"交易了但亏钱"必须区分报告,
  不允许用缩小止损去迁就预算。

## 决策三:不用 vn.py OptimizationSetting,自建进程池 + 模块级 worker

vn.py 自带的 `OptimizationSetting.run_optimization` 依赖数据库数据与内部 multiprocessing Pool;
本项目 15 分钟 K 线从不入库(只做内存回放,落库会被当成 1 分钟线读回、周期全错),无法直接套用。
方案:

- 模块级 `_backtest_one(data_file, params, start_iso, end_iso)`:入参全部是 str/dict/数值,
  Windows spawn 下可 pickle;worker 自行 `load_bars_csv` 并经 `backtest_lib.run_engine_bars`
  回放——回测内核仍是 vn.py `BacktestingEngine`,满足"基于 CtaBacktester"的要求;
- `ProcessPoolExecutor` 并行,`--workers 1` 走进程内串行(测试与调试的确定性降级路径),
  入口有 `if __name__ == "__main__"` 守卫;每进程独立 `@lru_cache` 按 CSV 路径缓存 K 线;
- **单池贯穿全部窗口(codex 审查后修正)**:进程池在 `main()` 创建一次并经 `run_window(..., executor=pool)`
  传入,而不是每次调度新建——否则 3 窗口 ×(训练+验证) 会创建 6 个池,每池重新 spawn、重新 import vnpy/pandas、
  重新解析全量 CSV,lru_cache 随池销毁完全失效;
- 有一个 `test_real_spawn_produces_same_results_as_serial` 真实双进程冒烟测试:多进程逻辑若退化成
  闭包/不可 pickle 对象,CI 能捕捉(其余调度测试用注入的假池,避免 Windows 反复 spawn);
- 用 `run_engine_bars` 而非 `run_backtest_bars`,是为了从 `engine.strategy` 读取预算弃单计数器;
  `backtest_lib.py` 的既有函数签名与行为零改动。

## 决策四:排名用原始夏普的确定性多级排序,不做邻域平滑

- 资格门槛:`fills >= 100` 且夏普非 NaN;
- 排序键:夏普降序 → 最大回撤金额升序 → 成交笔数降序 → fast 升序 → slow 升序。
  末两级保证完全平局时结果仍然可复现;取前 5 名代入本窗口验证段;
- 不使用 `optimize.smoothed()`:Walk-Forward 的训练与验证必须用同一把朴素尺子,
  邻域平滑属于 `optimize_15m.py` 单窗口选参的场景,引入平滑会让两个实验的口径不可比。

## 决策五:测试段隔离的三层护栏

1. 常量硬断言:模块级 `TEST_SEGMENT_START`,任何区段的起讫日期经 `_assert_pre_test` 校验,
   越界或方向错误直接 `ValueError`;
2. API 级反例测试:用测试段日期调用公开函数,断言抛错;
3. 源码扫描测试:测试直接读取本脚本源码,2024 及以后的年份字面量只允许出现在
   `TEST_SEGMENT_START` 定义行;脚本不提供 `--test` 或任何等价开关。
   **该层定位是防误改的提示网,不是强保证**:`datetime(2000+24, ...)` 之类的动态构造检测不到;
   真正的保证来自第 1 层——隔离断言在窗口构建与每次回测的 worker 内部各执行一次,
   伪造的越界窗口无论走串行还是真实 spawn 子进程都会被拦截(codex 审查已实测验证)。
   另:worker 切片后断言 `max(b.datetime) < TEST_SEGMENT_START`,保证即便 CSV 含测试段行,
   引擎/策略对象也永远收不到测试段 K 线。

## 夏普口径限制(沿用基线 ADR 的事后补充)

vn.py 按日历日分组 ×240 年化,夜盘与次日日盘被拆成两条日历日记录。本脚本的夏普只用于
**同一口径下的横向排序**,不可解释为年化收益,也不可与日线夏普直接比较;收益、净盈亏、
成本、回撤金额不受该口径影响。

## 结果(2026-11-10,按上述方案一次性运行,未改动任何参数/网格/切分)

3 个窗口各 31 组训练回测 + Top5 验证,共 108 次回测;没有窗口触发 INSUFFICIENT
(各窗口达标组合均 ≥ 5)。明细:`data/results/walk_forward_C15.csv`(不纳入版本控制)。

各窗口训练段第一名与其验证段表现:

| 窗口 | 训练第一名 (fast/slow) | 训练夏普 | 验证夏普 | 验证最大回撤 | 验证往返 |
|---|---|---|---|---|---|
| W1 | 10/80 | -2.77 | -3.29 | -20.8%(-2080 元) | 53 |
| W2 | 14/60 | -1.29 | -3.73 | -16.7%(-1674 元) | 59 |
| W3 | 30/80 | -3.21 | -3.46 | -12.7%(-1268 元) | 36 |

跨窗口汇总:第一名验证夏普均值 -3.49 / 中位数 -3.46;**15 组验证参数夏普全部为负,
正夏普窗口占比 0%**;验证段最差最大回撤 -2773 元(W2 的 14/50);预算弃单率全程 0%。

### 解读

1. **"矮子里拔将军"拔不出优势。** 三个窗口训练段的最优夏普本身就是负数(-1.29 ~ -3.21),
   即训练段上没有任何参数组合能盈利;Top5 外推到验证段后全部继续为负,不存在"训练有效、
   验证失效"的过拟合叙事,而是全网格、全时段的系统性亏损,与基线 ADR 的负面结论互相印证。
2. **预算弃单率 0% 是一个有信息量的零。** atr_mult 固定 1.5 时,15 分钟级别的止损距离
   乘以玉米合约乘数后都在 300 元以内,300 元硬预算在本网格下没有拦截任何交易——
   空仓/亏损不是预算造成的,不能用"放宽预算"改善结果。
3. **统计意义仍然不足。** 验证段往返笔数 36~76,全部低于 150 的统计意义门槛;
   但"全部为负"不需要显著性检验也是事实,门槛限制的只是正向结论的可信度。
4. **确定性已验证。** workers=1 串行与 workers=4 并行两次完整运行的数值完全一致;
   排名只依赖回测指标与确定性多级排序键,进程调度不影响结果。
5. 本次运行后未对网格、窗口、固定参数做任何调整;后续若要再跑属于新的研究决策,需新 ADR。

### 审查发现的两处统计修正(2026-11-10,codex 第二轮审查,不影响上述结果的数值)

1. **vn.py 的 `max_drawdown` 金额带负号**(如 -5522 表示回撤 5522 元)。首版实现按正数口径处理,
   导致汇总"最差回撤"被 0 吞掉、排名平局键方向反向;已按负号口径修正(`-maxdd_yuan` 升序、`min` 汇总),
   并复跑确认窗口排名与数值不变(平局键只影响完全平局的次序)。ADR `20261110-baseline-15m.md`
   结果表中的负号回撤为同一口径,先例一致。
2. **当前钉住的 vn.py 在 `calculate_statistics` 内对统计量做 `np.nan_to_num`**,"夏普可能为 NaN"对
   该版本不成立;`rank` 的 NaN 过滤与 `summarize` 的 isfinite 过滤保留,作为防升级/口径变化的防御,
   `summarize` 同时报告剔除数量,避免 NaN 静默压低正夏普窗口占比。

### 预算弃单率的解读边界

弃单率分母 = `skipped_by_budget + 往返笔数`(每次往返对应一次入场)。三类情形**不计入**分母,
读取时不得把弃单率误读为"总拦截率":① 段末仍持仓时的最后一笔开仓(奇数 fills 的 `//2` 截断,
原始 fills 已保留在 CSV 供核对);② 连亏熔断 `guard.can_open` 拦截的入场信号;③ 全程无信号的时段
(分母为 0 时弃单率记 0.0,与"交易很多且零弃单"语义不同)。

## 已知局限

1. 三个验证段每个只有 6 个月(约 2750 根 15m K 线),单窗口往返笔数可能低于 150 的
   统计意义门槛;跨窗口聚合只能缓解、不能消除样本量问题。
2. 单品种(玉米)、单一复权方式(差额复权,越早价格水平偏离越大)、一套成本假设;
   结论的外推范围有限。
3. 成交模型仍是"下一根开盘价附近限价成交 + 本地停止单",无排队与盘口冲击,
   SimNow/实盘滑点只会更差。
4. 训练段跨窗口重叠意味着三个验证结果并非完全独立的统计样本,聚合占比是描述性指标,
   不做显著性检验。
